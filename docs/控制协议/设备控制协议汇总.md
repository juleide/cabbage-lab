# 设备控制协议汇总

整理日期：2026-10-31。

本文汇总本目录中 5 份设备接入说明，涉及 3 类传感采集设备、2 类运动执行设备。协议包括 Modbus RTU、厂家自定义串口协议和 USB 自定义数据流。

**本文是资料总结，不代表已通过实机验证。** 示例报文按十六进制原始字节展示，不发送十六进制字符串。未明确的参数、行为和推导结果不能当作已验证事实。

## 一、协议总览

| 设备 | 接口与通信参数 | 协议 | 核心功能 | 主要待确认项 |
| --- | --- | --- | --- | --- |
| 57 步进电机 / 力川单轴驱动器 | RS485；9600 / 19200 / 38400 / 115200；串口格式按设备配置 | Modbus RTU | 定位、点动、回零、停止、状态与位置读取 | 实物通信配置、部分运动参数字段及单位 |
| 升降装置霍尔控制器 | RS232：38400、8N1；RS485 参数待核实 | 自定义 `AA … FF` 帧 | 上升、下降、停止、目标位置运动、位置记忆 | RS485 高度查询、反馈机制、到位与停止判据 |
| 拉力传感器 GJ9658B | RS485；默认 9600、8N1 | Modbus RTU | 重量读取、去皮、两点校准、滤波配置 | 标定单位与小数位、部分寄存器类型及响应行为 |
| 直线位移传感器 / 电子尺模块 | RS485；默认 9600、8N1、站号 1 | Modbus RTU；分 P / G 两套寄存器表 | 位移读取、量程与通信参数配置 | 实际模块型号、通道数、校准流程 |
| 电子皮肤 64×64 | USB 2.0、5 V | 自定义行数据包 | 接收并重组 4096 点阵列数据 | SDK、端点、启停指令、CRC、物理量换算 |

## 二、57 步进电机：力川 RS485 单轴驱动器

### 1. 通信与数据格式

- 两个单轴驱动器共用一个 RS485 串口，各驱动器使用唯一站号，主机逐台访问。
- 功能码：`0x03` 读寄存器、`0x06` 写单寄存器、`0x10` 写多个寄存器。
- 每个寄存器高字节先发；32 位定位目标高字在前、低字在后。
- CRC 使用 CRC-16/MODBUS，低字节先发。
- 地址按文档中的十六进制协议地址使用，不加 `40001`，不额外加减 1。
- 波特率和串口格式必须与实物一致，不能将其他设备的默认 9600/8N1 套用于电机。

### 2. 关键寄存器

| 地址（十六进制） | 功能 |
| --- | --- |
| `0x0004` | 状态字：到位、回零完成、运行、故障、使能、正负软限位 |
| `0x0008～0x0009` | 当前位置，高字 / 低字 |
| `0x000A` | 当前速度 |
| `0x0030～0x0032` | JOG 参数组 |
| `0x0033～0x0038` | 定位参数组 |
| `0x0037～0x0038` | 32 位目标脉冲数，高字 / 低字 |
| `0x0040～0x0045` | 回零参数组 |
| `0x004E` | 运动控制字 |
| `0x004F` | 辅助控制命令 |

### 3. 常用控制命令

向 `0x004E` 写入：

| 值 | 动作 |
| --- | --- |
| `0x0001` | 相对定位 |
| `0x0003` | 绝对定位 |
| `0x0005` | 相对定位，允许打断当前运动 |
| `0x0007` | 绝对定位，允许打断当前运动 |
| `0x0008` | JOG 点动 |
| `0x0010` | 回零 |
| `0x0020` | 停止 |
| `0x0040` | 软件急停，不等同硬接线急停 |

向 `0x004F` 写入：`0x0200` 保存参数、`0x0300` 清告警、`0x0400` 清当前位置、`0x0500` 使能、`0x0600` 释放电机。参数保存不应在每次运动后自动执行。

### 4. 典型定位流程

1. 配置速度、加减速等参数。
2. 一次写入 `0x0037～0x0038` 的目标脉冲数。
3. 写 `0x004E` 触发运动。
4. 轮询状态字和位置，判断完成或故障。

示例：设置目标为 1000 pulse，再触发相对定位，站号为 1。

```text
写目标：01 10 00 37 00 02 04 00 00 03 E8 B1 E3
触发：  01 06 00 4E 00 01 28 1D
```

写入应答不代表运动完成；通信超时后不能盲目重发运动触发命令。连接验证仅使用只读查询，不自动运动、回零、清错或清当前位置。

详见：[57步进电机-力川RS485驱动接入说明](57步进电机-力川RS485驱动接入说明.md)。

## 三、升降装置：霍尔控制器

文档描述的是电动升降霍尔控制器，不是气压阀控制协议。

### 1. 帧格式

```text
AA LEN CMD DATA... FF
```

- `LEN` 包含自身、命令和数据，不包含帧头 `AA`、帧尾 `FF`；整帧长度为 `LEN + 2`。
- 已给格式中没有站地址，也没有 CRC，不能按 Modbus 处理或自行追加 CRC。
- RS232 明确为 38400、8N1；RS485 可将此作为待验证配置，不能视为已确认。

### 2. 控制命令

| 功能 | 报文 / 命令 |
| --- | --- |
| 上升 | `AA 03 02 00 FF` |
| 下降 | `AA 03 03 00 FF` |
| 停止 | `AA 03 04 00 FF` |
| 保存记忆位置 | `AA 03 05 n FF`，n 为二进制字节 0～3 |
| 运行至记忆位置 | `AA 03 06 n FF` |
| 查看记忆位置 | `AA 03 07 n FF`，返回命令及关联方式待确认 |
| 系统复位 | `AA 03 08 00 FF`，具体运动行为未定义 |
| 设置当前位置信息 | 命令 `0x60`，不是运动命令 |
| 运行到目标位置 | 命令 `0x80` |

### 3. 高度数据

位置编码为 5 字节 ASCII `DDD.d`。`0x60`、`0x80` 明确以 cm 为单位，`0x01` 高度反馈按相同单位解释，仍需实机核对。编码步长为 1 mm，不代表测量精度或到位精度。

示例：运行到 12.3 cm，数据域为 ASCII `012.3`。

```text
AA 07 80 30 31 32 2E 33 FF
```

高度反馈命令为 `0x01`：

```text
AA 07 01 [5字节位置ASCII] FF
```

编码容量不代表实际行程，发送目标前必须检查实际机械范围。

### 4. 关键限制

- RS232 明确有主动高度上传；RS485 文档对主动上传与查询反馈的描述矛盾，且未提供完整当前高度查询帧。
- `AA 03 09 00 FF` 在 RS232 下用于清错，在 RS485 下用于查询错误，且查询会自动清除错误码，不能作为普通心跳。
- 没有明确的到位标志、停止完成反馈或通用 ACK；主动高度反馈不能当作动作 ACK。
- 无站地址字段，不能默认多个控制器可共用同一 RS485 总线寻址。
- 连接时不应自动复位、清错、修改当前位置信息或运行到记忆位置；断线重连不自动续跑。

详见：[升降气缸-霍尔控制器接入说明](升降气缸-霍尔控制器接入说明.md)。

## 四、拉力传感器：GJ9658B

### 1. 通信与数值格式

- RS485、Modbus RTU，默认 9600、8N1，功能码为 `0x03 / 0x06 / 0x10`。
- 实际站号为“拨码值 + 寄存器 10 的偏移”，不一定固定为 1。
- 实时重量为 int32，低字在前、高字在后；每个字内部仍为高字节先发。
- 单位与小数位由标定约定，协议本身不提供，不能直接将读数标为 N。

读取实时重量，站号为 1：

```text
请求：01 03 00 00 00 02 C4 0B
响应：01 03 04 04 D2 00 00 5B 3A
```

数据区 `04 D2 00 00` 合成为整数 1234；若标定约定两位小数，则值为 12.34。负数按 int32 补码解释。

### 2. 关键寄存器

以下地址为十进制、从 0 开始：

| 地址 | 功能 |
| --- | --- |
| 0～1 | 实时重量，int32 |
| 2～3 | 当前内码，符号解释待确认 |
| 4～5 / 6～7 | 零点内码 / 砝码内码 |
| 8～9 | 标定砝码重量，int32 |
| 10 / 11 | 站地址偏移 / 波特率 |
| 12 | 平均滤波长度，1～30 |
| 14 | 分度值，即输出跳动步长 |
| 16 | 采集速度：0 为 12 Hz，非 0 为 50 Hz |
| 17 | 写 1 去皮；写 2 取消去皮 |
| 18 | 写 1 零点校准；写 2 砝码点校准 |
| 19 | 写十进制 12345 恢复出厂，仅限明确确认后的维护操作 |
| 20 | 开机置零 / 动态追零使能 |
| 27 | 卡尔曼滤波使能 |

### 3. 校准与时序

两点校准流程：

1. 若使用过去皮，先向地址 17 写 2 取消去皮。
2. 空载稳定后，向地址 18 写 1。
3. 加载已知砝码并稳定后，向地址 18 写 2；砝码应大于传感器总量程的十分之一。
4. 向地址 8～9 一次写入按约定小数位放大的 int32 砝码重量，低字在前。

任何写指令发出后，至少等待 500 ms 才能发下一条指令；收到回显也不能省略等待。地址 17、18 执行后自动清零，不需另发清零指令。

### 4. 关键限制

- 地址 `254 / 0xFE` 是厂家定义的特殊响应地址，多台设备会同时应答，只能在总线仅有一台设备时使用，不能用于多设备扫描。
- 采集速度不等于主机轮询频率；滤波、追零会改变动态拉力表现，不能在连接时自动修改。
- `0x10` 正常响应按标准应返回起始地址和数量，不回显全部数据；本设备实际行为待联调确认。
- 写超时不代表命令未执行，校准、去皮、恢复出厂不能盲目重发。
- 通信失败不得用 0 替代有效测量值；上电读数为 0 也不代表已经校准。

详见：[拉力传感器-GJ9658B接入说明](拉力传感器-GJ9658B接入说明.md)。

## 五、直线位移传感器 / 电子尺模块

### 1. 通信与协议

- RS485、Modbus RTU，默认 9600、8N1、站号 1。
- 原数据为 uint16；量程变换结果为 ABCD 大端 float32，高字在前。
- 波特率配置值为“实际波特率 ÷ 100”，例如 9600 写十进制 96。
- 存在 P、G 两套不兼容寄存器表，必须根据实物选择，不能混用或试写识别。

### 2. 两套寄存器对照

以下地址为十进制、从 0 开始：

| 功能 | P：MM-V05-485-R 专用模块 | G：通用采集器 |
| --- | --- | --- |
| 原数据 | 0，归一化 0～5000 | 0 / 1 / 2，对应 CH1 / CH2 / CH3，实际通道待确认 |
| 换算结果 float32 | 2～3 | 6～7 / 8～9 / 10～11 |
| 站号 / 波特率 | 4 / 5 | 4 / 5 |
| 量程上限 / 下限 | 8～9 / 10～11 | CH1 为 14～15 / 16～17 |
| ADC 校准 | 6 / 7，新尺校准流程待确认 | 出厂校准参数，用户勿动 |
| 模块重启 | 29 写非 0 | 34 写非 0 |

G 的地址 29 是 CH3 量程下限的一部分，不是重启命令。通用采集器的输入范围取决于实际型号，不能假定同一模块可切换电流和全部电压输入。

### 3. 位移解析

P 原数据可按已确认的实际量程换算：

```text
position = lower + raw / 5000.0 * (upper - lower)
```

例如量程确认为 0～700 mm 时，raw = 2500 对应 350 mm；700 mm 只是资料示例，不是默认行程。不能将地址 12 的裸 ADC 值代入此公式。

G 按实际输入型号和标定关系换算：

```text
position = lower + (raw - rawMin) / (rawMax - rawMin) * (upper - lower)
```

要求 `rawMax > rawMin`。超出合理范围的数据应标记异常，不静默截断为端点。

也可直接读取模块的 float32 换算结果，但只有模块量程已按 mm 配好，才能直接标为 mm，不能重复缩放。必须一次读取完整两个寄存器，按大端 IEEE 754 解析，并检查有限值及合理范围。

```text
P 读源数据：    01 03 00 00 00 01 84 0A
P 读换算位移：  01 03 00 02 00 02 65 CB
G 读CH1换算值： 01 03 00 06 00 02 24 0A
```

### 4. 关键限制

- 此模块仅测量与配置，不控制机械运动。
- P 的 `0x10` 支持存在文档歧义，写 float32 前需确认。
- 原资料中的“写地址 0”示例与只读定义冲突，禁止发送。
- 没有定义去皮或自动置零寄存器；相对零点应由应用保存软件偏移，保留原始读数。
- 波特率重启生效；G 改站号重启生效，P 改站号时机待确认。
- 未规定统一写后等待，不能套用拉力模块的 500 ms。

详见：[直线位移传感器-电子尺RS485采集接入说明](直线位移传感器-电子尺RS485采集接入说明.md)。

## 六、电子皮肤：64×64 USB 采集卡

### 1. 连接与控制

- USB 2.0、USB 5 V 供电，通过厂家 SDK 或 USB 库访问。
- 部分 Windows 板卡要求 WinUSB，部分版本涉及 `key.txt` 授权。
- 当前资料没有提供握手、启动、停止及参数配置的具体下行字节序列，不能从 GUI 按钮推定硬件命令。
- VID/PID、接口、端点和传输类型均未提供，不能默认当作虚拟串口或 HID。
- 依板卡版本，上电后可能需等待 5～30 秒再连接或启动，实际就绪时序待确认。

项目规定 USB 连接按不同 REV 区分按压与抓取采集卡；串口模式每个采集器分别绑定独立串口。但厂家资料仅明确 USB 物理接口，尚不能证明存在虚拟串口。实际接入方式须待 SDK 和设备枚举信息确认，不将项目配置规则当作物理协议依据。

### 2. 上行行包结构

每包是一行 64 点，一帧 64 行，共 4096 点。

```text
AA 10 33 LEN FRAME ROW [128字节像素数据] [2字节CRC]
```

| 字段 | 说明 |
| --- | --- |
| 包头 | 固定 `AA 10 33` |
| 包长度 | 按字段推导为 136 字节，即 `0x88`，待抓包核实 |
| 帧号 | 0～255，需处理回绕 |
| 行号 | 0～63 |
| 像素 | 每点 16 bit，大端，共 128 字节 |
| CRC | 算法、精确覆盖范围及字节序均待确认 |

一帧行包总量按结构推导为 `64 × 136 = 8704` 字节，不含可能的 USB 额外封装；纯像素数据为 8192 字节。USB 单次读取不一定对应一个完整行包。

### 3. 数据重排与组帧

行内数据是步长 8 的交织顺序，不是自然列序。零起始传输下标 `i` 对应：

```text
column = (i % 8) * 8 + floor(i / 8)
matrix[row][column] = received_data[i]
```

接收端需要缓冲半包、拆分粘包，并按设备、连接会话和帧周期隔离组帧。同一帧的 0～63 行全部收到后才形成完整矩阵，重复行不增加行数，不能用旧帧补缺行；帧号需处理 `255 → 0` 回绕，重连时清空残包和未完成帧。

### 4. 关键限制

- CRC 不能默认使用 Modbus 算法；未确认时只能进行结构解析，保留“未校验”状态。
- 最高位被描述为符号位，但负数编码未明确，应先保留原始 uint16，不能直接假定为 int16 补码。
- 电压比例、压力 / 力标定关系尚缺失，原始值不得标注为 V、mV、N、Pa 或 kPa。
- 像素重排不定义实物方向、镜像或旋转，需用已知受压位置核对。
- 完整设备控制链路需要厂家 SDK、USB 指令及授权流程，指令未确认前不发送猜测报文。

详见：[电子皮肤64X64-USB采集卡接入说明](电子皮肤64X64-USB采集卡接入说明.md)。

## 七、接入时最重要的区别

| 对比项 | 步进电机 | 拉力模块 | 位移模块 | 升降控制器 | 电子皮肤 |
| --- | --- | --- | --- | --- | --- |
| 核心数据格式 | 位置高字在前 | int32 低字在前 | uint16 / ABCD float32 | ASCII 位置 | 大端 16 位原始点值 |
| 校验 | Modbus CRC | Modbus CRC | Modbus CRC | 已给格式无 CRC | CRC 未知 |
| 完成判据 / 时序 | 状态字及位置 | 写后至少等 500 ms；不等同测量稳定判据 | 响应及读回，时序待确认 | ACK / 到位判据未明确 | 同帧收齐 64 行，保留校验状态 |
| 当前主要缺口 | 运动参数细节 | 标定约定及部分语义 | 实物型号与校准 | RS485 查询及执行反馈 | USB 访问、下行控制、CRC、换算 |

### 通用接入原则

- 串口按设备类型分配，除电子皮肤外，同类型多个设备共用串口，不同类型分别使用各自串口；电子皮肤串口模式每台独立端口，实际 USB 接入方式仍需厂家资料确认。
- 同一 RS485 总线使用一致通信参数和唯一站号；同一串口只保留一个未完成请求。
- 接收端处理半包、粘包、残帧、异常响应和迟到响应；Modbus 应答校验站号、功能码、长度和 CRC，写响应还要匹配地址及值或数量。
- 通信端口打开、收到有效报文和设备允许运动是不同状态；连接时只做已确认无副作用的验证。
- 通信失败和数据无效不得伪装成 0；主机接收时间不等于设备采样时间。
- 未经明确操作，不自动运动、复位、清错、去皮、校准、恢复出厂或修改位置基准；命令超时不等于未执行。
- 软件停止或急停命令不能替代独立的硬件安全措施。

总体判断：步进电机、拉力模块和位移模块已有明确的 Modbus 接入框架；升降控制器可整理出运动指令，但反馈闭环仍不完整；电子皮肤的数据包结构较清楚，完整设备控制链路仍依赖厂家 SDK 和补充协议。
