# 直线位移传感器 / 电子尺 RS485 通信协议

本文保留位移采集与模块配置所需的协议。资料包含两套不兼容寄存器表，须先按实物确认档案，禁止试写识别；本模块只负责测量与配置，不提供机械运动控制接口。未进行实机通信验证。

| 档案 | 适用模块 | 来源文件 |
| --- | --- | --- |
| P | 电子尺专用插头模块 MM-V05-485-R | `262e156bf8a7566e722019b0f10dc564.pdf`（正文《电子尺转485说明书》） |
| G | 通用采集器 MM-I20-485、MM-V5-485、MM-V10-485，具体型号需确认 | `电子尺采集器.pdf`（正文《模拟量转485模块说明书》） |

以下地址均为从 0 开始的十进制协议地址，报文为十六进制原始字节；PLC 编号仅作对照，`PLC地址 = 40001 + 协议地址`，不能直接发送 40001。

## 一、通信基础参数

| 项目 | 参数 |
| --- | --- |
| 通信方式 | RS485，Modbus RTU，主机请求、从机应答 |
| 出厂参数 | 9600 bit/s、8 数据位、无校验、1 停止位（8N1） |
| 出厂站地址 | 1；可设 1～247，多设备地址必须唯一 |
| 波特率选项 | 1200、2400、4800、9600、19200、38400、57600、115200 |
| 波特率寄存器值 | 波特率 / 100，分别为 12、24、48、96、192、384、576、1152 |
| 功能码 | `0x03` 读保持寄存器；`0x06` 写单寄存器；`0x10` 写多寄存器，P 的支持声明存在遗漏，需确认 |
| 寄存器字节序 | 每个 16 位寄存器高字节先发 |
| float32 字序 | ABCD，高字在低地址，按大端 IEEE 754 单精度解析 |
| CRC 字节序 | 低字节先发 |
| 帧间隔 | 原文要求开始 / 结束静默不少于 4 个字符时间，不是填充字节；高速通信还应满足 RTU 通用时序要求 |

同类型位移模块共用一个独立串口 / RS485 总线，按唯一站地址串行轮询，不与其他类型设备共用串口。多个出厂地址同为 1 的模块应逐台改址后接入。G 支持校验配置，P 未提供此能力；同一总线必须使用相同字符格式。

原文未提供采样率、推荐轮询周期、最大读写数量、响应超时及写后等待，不套用其他设备的 500 ms 等待规则。帧间隔不等于设备处理时间。

## 二、帧结构与校验

以下 N 为寄存器数量：

```text
03 请求（8 字节）：
站号 03 地址Hi 地址Lo 数量Hi 数量Lo CRClo CRChi
03 正常响应（5 + 2*N 字节）：
站号 03 字节数(2*N) [寄存器Hi Lo ...] CRClo CRChi

06 请求 / 正常响应（8 字节，回显地址和值）：
站号 06 地址Hi 地址Lo 数值Hi 数值Lo CRClo CRChi

10 请求（9 + 2*N 字节）：
站号 10 地址Hi 地址Lo 数量Hi 数量Lo 字节数(2*N) [数据...] CRClo CRChi
10 正常响应（8 字节，不回显数据区）：
站号 10 地址Hi 地址Lo 数量Hi 数量Lo CRClo CRChi

标准异常响应（5 字节）：
站号 (请求功能码 | 0x80) 异常码 CRClo CRChi
```

CRC-16/MODBUS：初值 `0xFFFF`，右移多项式 `0xA001`，最终异或为 0；覆盖站号到数据末尾，不含 CRC 自身。修改任一字段必须重算 CRC。

接收核验站号、功能码、长度、字节数和 CRC，写响应还须匹配地址、值或数量。没有固定 AA / FF 帧头尾，不发送十六进制字符串文本。具体设备异常码未列出。

## 三、P 档案寄存器：MM-V05-485-R

| 地址 | 功能 | 类型 / 权限 | 定义与取值 |

| 1 | 模块温度 | uint16，只读 | 0～60 ℃ |
| 2～3 | 量程变换结果 | float32，只读 | 高字在 2，低字在 3；按已设量程换算 |
| 4 | 站地址 | uint16，读写 | 1～247；生效时机及掉电保存规则未明确 |

| 7 | ADC 校准下限 | uint16，读写 | 0～4095，通常为 0，无特殊情况不要修改 |

## 四、G 档案寄存器：通用采集器

输入型号的原数据范围：MM-I20-485 为 4～20 mA 对应 4000～20000；MM-V5-485 为 0～5 V 对应 0～5000；MM-V10-485 为 0～10 V 对应 0～10000。不能据此认定同一模块可切换全部输入类型。

| 地址 | 功能 | 类型 / 权限 | 定义与取值 |
| --- | --- | --- | --- |
| 0 / 1 / 2 | CH1 / CH2 / CH3 原数据 | uint16，只读 | 范围依实际输入型号 |
| 3 | 保留 | uint16，只读 | 不写入，不定义业务用途 |
| 4 | 站地址 | uint16，读写 | 1～247；重启生效，掉电保存 |

| 6～7 | CH1 量程变换结果 | float32，只读 | ABCD，高字在前 |
| 8～9 | CH2 量程变换结果 | float32，只读 | 同上 |
| 10～11 | CH3 量程变换结果 | float32，只读 | 同上，实际 CH3 支持需确认 |
| 12 / 13 | CH1 校准上限 / 下限 | uint16，读写 | 出厂校准值，用户勿动 |
| 14～15 / 16～17 | CH1 量程上限 / 下限 | float32，读写 | 用户设定，ABCD |

| 20～21 / 22～23 | CH2 量程上限 / 下限 | float32，读写 | ABCD |

## 五、位移解析与配置规则

### 1. 原数据换算

P 地址 0 的 uint16 采用高字节在前。按归一化比例推导的主机换算：

```text
position = lower + raw / 5000.0 * (upper - lower)
```

例如已确认量程 0～700 mm 时，raw 为 0 / 2500 / 5000 对应 0 / 350 / 700 mm。700 mm 仅为资料示例，不能当作现场默认行程。不要将地址 12 的 0～4095 裸 ADC 代入此公式。

G 依据实际输入型号和标定关系换算：

```text
position = lower + (raw - rawMin) / (rawMax - rawMin) * (upper - lower)
```

要求 `rawMax > rawMin`。范围、方向和单位由配置保存；异常越界值不静默截断为端点。

### 2. float32 读写

P 读取地址 2～3，G 按通道读取 6～7 / 8～9 / 10～11。一次读完整两个寄存器，按大端 IEEE 754 解析，例如 JavaScript `DataView.getFloat32(offset, false)`；不是 int32，也不是低字在前。

| 数据区 ABCD | float32 |
| --- | --- |
| `00 00 00 00` | 0.0 |
| `43 AF 00 00` | 350.0 |
| `44 2F 00 00` | 700.0 |
| `C3 AF 00 00` | -350.0，解析测试，不证明实物允许负行程 |

只有模块上下限已按 mm 标定，换算结果才能标为 mm，不重复缩放。float32 写入优先用已确认支持的 `0x10` 一次写两个寄存器；拒绝 NaN / Infinity，接收校验有限值及合理范围。

### 3. 地址、通信参数与重启

- uint16 参数使用 `06`。站地址写 4，波特率写 5；9600 写十进制 96，即 `00 60`，不是 `25 80`。
- 波特率重启生效；G 改站地址明确重启生效，P 改址时机待确认，应单机操作并验证。
- P 重启地址为 29（`00 1D`），G 为 34（`00 22`），禁止用重启命令探测型号或自动恢复通信。
- 配置前备份，暂停采集并逐项读回。保存耗时、重启前是否回复未明确，写超时不代表未执行，不盲目重发。
- 两份资料均未定义去皮 / 自动置零寄存器；相对零点由应用保存软件偏移，保留原始读数，不套用其他设备命令。

## 六、报文示例

站号均为 1。以下 8 条完整报文已复算 CRC，推导帧不代表实机支持；改站号必须重算。

### 1. 只读采集

| 档案 / 用途 | 请求 |
| --- | --- |
| P 源数据 / G CH1 原数据，0 读 1 个，原文示例 | `01 03 00 00 00 01 84 0A` |
| P 换算位移，2 读 2 个，按表推导 | `01 03 00 02 00 02 65 CB` |
| P ADC 裸值，12 读 1 个，按表推导 | `01 03 00 0C 00 01 44 09` |
| G CH1 换算值，6 读 2 个，按表推导 | `01 03 00 06 00 02 24 0A` |

原文地址 0 应答示例：`01 03 02 05 44 BB 27`。数据 `05 44` = uint16 1348；若为已标定 0～700 mm 的 P，主机换算为 188.72 mm，而非 1348 mm。

### 2. 量程写入（推导报文，仅受控配置使用）

| 档案 / 用途 | 请求 |
| --- | --- |
| P 上限 700.0，写 8～9 | `01 10 00 08 00 02 04 44 2F 00 00 D7 30` |
| P 下限 0.0，写 10～11 | `01 10 00 0A 00 02 04 00 00 00 00 73 D0` |
| G CH1 上限 700.0，写 14～15 | `01 10 00 0E 00 02 04 44 2F 00 00 57 1A` |

仅在型号、实际量程与 `0x10` 支持已确认后发送；上下限为两个事务，中间状态不构成完整配置。不能跨地址大块写入覆盖只读、出厂校准或重启寄存器。

## 七、接收调度与原文歧义

- **总线事务**：同一串口仅一个未完成请求，处理半包、多个帧合并、残帧与迟到响应。`03` 回复没有起始地址，超时后的同站旧回复不能误配到下一次不同查询。
- **数据有效性**：坏 CRC、异常响应、超时、非有限浮点及不合理范围标记无效 / 过期，不输出为 0 mm。主机接收时间不等于采样时间，协议未提供采样序号或时间戳。
- **档案隔离**：读取地址 0 成功不能区分 P / G。尤其地址 2～3、6～7、12～13、29 的功能不同，禁止混用。
- **只读写入示例错误**：P 第 19 页、G 第 13 页给出写地址 0 的示例，与寄存器只读定义冲突，禁止发送；其 CRC 正确不证明允许写入。原写响应中的 `10x84` 亦为排版错误。
- **波特率地址错误**：P 第 17 页说明标题写“0017寄存器”，与表中地址 5 冲突；不向 17 或 `0x17` 写波特率，以地址 5 为候选并核实。
- **功能码支持**：P 声明仅列 03 / 06，却另给“16 功能码”帧表；十进制 16 即 `0x10`，不是 `0x16`，支持情况待确认。原回复表将单个数据字节长度写为 2 字节，应按寄存器 2 字节和实际字节数解析。
- **接入前确认**：P 完整 ADC 校准流程、改址时机、参数保存与 `0x10` 支持；G 实际型号、通道数和校验格式；两类模块的响应超时、写后等待、异常浮点及重启应答行为。
