# 拉力传感器 GJ9658B 通信与控制协议

依据《GJ9658B 数字信号模块使用说明书》V2.0（2022-05-25）整理。地址均为十进制、从 0 开始的协议地址，报文字节均为十六进制。示例 CRC 已核算，未进行实机通信验证。

## 一、通信基础参数

| 项目 | 参数 |
| --- | --- |
| 通信方式 | RS485 |
| 协议 | Modbus RTU，主从方式，每次通信由主机发起 |
| 出厂默认 | 9600 bit/s、8 数据位、1 停止位、无校验（8N1） |
| 支持波特率 | 寄存器 11 列出 2400、4800、9600、19200、38400；规格页未列 2400，该档待实机确认 |
| 可修改通信参数 | 仅波特率；其他校验方式需订货前说明 |
| 总线能力 | 9600 bit/s 时最大传输距离标称 1200 m，最多级联 32 个设备 |
| 站地址 | 实际站地址 = 拨码开关值 + 寄存器 10 的偏移值；偏移默认 0，示例站号 1 不代表出厂固定站号 |
| 特殊地址 | 254（`0xFE`），厂家称“广播地址”，无论实际站地址为何都会响应；仅允许总线上只有一台设备时使用，多设备会同时回复而冲突 |
| 读取时序 | 模块收到读指令后立即执行并返回数据 |
| 写入时序 | 执行约需 0.5 秒；发送任何写指令后，至少等待 500 ms 再发送下一条指令，不以收到回显代替等待 |

同类型拉力模块共用一个串口 / RS485 总线，每台使用唯一站地址，由主机串行轮询；不同类型设备不共用该串口。地址 254 不是标准 Modbus 地址 0 的无响应广播，不用于多设备扫描。

## 二、寄存器表

共 30 个 16 位保持寄存器，地址 0～29。**保持寄存器不等于全部掉电保存**，实时值、计数及命令寄存器按下表处理；未明确的读写权限不自行推定。

| 地址 | 名称 | 类型 | 说明 |
| --- | --- | --- | --- |
| 0～1 | 实时重量 | int32 | 低字在 0，高字在 1；常规采集读取此项，不保存，上电默认 0 |
| 2～3 | 当前内码值 | 表列 uint32 | 当前采集信号的内码，不保存；原文符号定义有冲突，见下文 |
| 4～5 | 零点内码值 | 表列 uint32 | 重量为 0 时的内码；可直接写，也可向 18 写 1 自动复制当前内码 |
| 6～7 | 砝码内码值 | 表列 uint32 | 加载标定重量时的内码；可直接写，也可向 18 写 2 自动复制当前内码 |
| 8～9 | 砝码重量值 | int32 | 不带小数点，按约定精度放大；例如 100.00 写 10000 |
| 10 | 站地址偏移 | uint16 | 默认 0；实际站地址 = 拨码值 + 偏移；合法上限及改址生效时机未明确 |
| 11 | 波特率 | uint16 | 下次重启生效；允许 2400 / 4800 / 9600 / 19200 / 38400，其他值自动赋为 9600 |
| 12 | 滤波长度 | uint16 | 1～30，平均值滤波次数；越大越平稳，但跟随越慢 |
| 13 | 保留 | — | 不得写入 |
| 14 | 分度值 | uint16 | 输出最小跳动步长；2 表示仅输出偶数，5 表示仅输出 5 的倍数 |
| 15 | 追零次数 | uint16 | 用于读取追零成功次数，每次成功加 1；不保存，开机清零 |
| 16 | 采集速度 | uint16 | 0 = 12 Hz，非 0 = 50 Hz；不是通信波特率 |
| 17 | 去皮操作 | uint16 命令 | 写 1：手动追零 / 去皮；写 2：清除追零值 / 取消去皮；执行后自动清零 |
| 18 | 校准操作 | uint16 命令 | 写 1：当前内码存入零点内码；写 2：当前内码存入砝码内码；执行后自动清零 |
| 19 | 恢复出厂 | uint16 命令 | 写十进制 12345，恢复所有寄存器为出厂默认值 |
| 20 | 追零使能 | uint16 | 0：关闭；1：仅开机置零；2：仅动态追零；3：开机置零后自动动态追零 |
| 21 | 开机置零静止范围 | uint16 | 多次重量波动小于该值时判定静止 |
| 22 | 动态追零静止范围 | uint16 | 动态追零的静止判定范围 |
| 23 | 开机置零置零范围 | uint16 | 最大置零偏差；原文判定为“置零值 + 当前重量值”大于此值时不置零，符号及边界待确认 |
| 24 | 动态追零追零范围 | uint16 | 最大追零偏差；原文说明误写“开机置零”，具体判定语义待确认 |
| 25 | 开机置零静止次数 | uint16 | 按采样次数而非固定时间判断；如 10 表示 10 次重量波动满足静止范围 |
| 26 | 动态追零静止次数 | uint16 | 同上，实际时间取决于采集速度 |
| 27 | 卡尔曼滤波使能 | uint16 | 0：禁止；1：使能 |
| 28～29 | 去皮值 | 原表标 uint16，组合方式未明确 | 去皮及自动置零保存的去皮值；原表合并两个地址但标为 16 位，确认前不自行定义类型或写入方式 |

### 32 位解析与缩放

每个寄存器内高字节先发，两个寄存器组成 32 位量时低地址为低字。必须一次读写完整两个寄存器，不能只读低字，也不能按浮点数解释。

原文第 7 页要求所有 32 位读写按有符号方式处理，但第 8 页将内码类标为无符号，当前内码说明又称有符号。重量、砝码重量明确按 int32；内码保留原始 32 位字，符号解释待厂家确认，不影响读取重量。

以下 `data` 仅表示重量响应中的 4 字节数据区：

```text
lowWord  = data[0] * 256 + data[1]
highWord = data[2] * 256 + data[3]
u32      = highWord * 65536 + lowWord
raw      = u32 >= 2147483648 ? u32 - 4294967296 : u32
value    = raw / pow(10, decimalPlaces)
```

小数位和单位由标定约定、由主机保存，协议不携带对应元数据；不能直接把原始重量整数当作 N。

| 数据区（低字在前） | int32 解析结果 |
| --- | --- |
| `04 D2 00 00` | 1234；若约定 2 位小数，显示 12.34 |
| `FB 2E FF FF` | -1234 |
| `11 70 00 01` | 70000 |

## 三、关键操作流程

### 1. 两点校准

若之前使用过去皮，先向地址 17 写 2 取消去皮。随后完成以下三项，每次写入后均等待至少 500 ms：

1. 空载并稳定后，向地址 18 写 1，执行零点校准。
2. 加载已知砝码并稳定后，向地址 18 写 2，执行砝码点校准；砝码应大于传感器总量程的十分之一。
3. 向地址 8～9 一次写入 int32 砝码重量，例如约定两位小数、100.00 kg 对应写入 10000。

原文允许三项调整顺序，但必须全部完成；仅执行部分步骤后的读数不代表最终结果。校准参数掉电保存，通常只需校准一次；更换传感器需重新校准。校准前机械、电气连接和走线应稳定，校准后不应大幅移动或弯折导线。

### 2. 去皮 / 清零与取消去皮

- 去皮：空载时向地址 17 写 1，消除零点漂移；净重应用也可按明确操作以当前容器负重作为零点。去皮值掉电保存。
- 取消去皮：向地址 17 写 2，清除已保存的去皮值；曾用过去皮时，重新校准前必须执行。
- 地址 17、18 执行后自动清零，无需再发送清零指令；读回 0 不代表操作失败。

### 3. 恢复出厂

向地址 19 写十进制 12345（`0x3039`）。该操作会恢复所有寄存器为出厂默认值，仅作为明确确认后的维护操作，不用于自动故障恢复。

## 四、指令示例

以下均以站地址 `01` 为例。改变站地址、地址、数量或数值后，必须重新计算 CRC。

### 1. 读取实时重量：功能码 03

```text
发送：01 03 00 00 00 02 C4 0B
回复：01 03 04 04 D2 00 00 5B 3A
```

请求中 `00 00` 是起始地址，`00 02` 是寄存器数量。回复中 `04` 是数据字节数，低字 `04 D2`、高字 `00 00` 合并为 1234。

### 2. 单寄存器写入：功能码 06

正常响应原样回显请求，均为 8 字节。

| 操作 | 请求报文 |
| --- | --- |
| 零点校准，18 写 1 | `01 06 00 12 00 01 E8 0F` |
| 砝码点校准，18 写 2 | `01 06 00 12 00 02 A8 0E` |
| 去皮，17 写 1 | `01 06 00 11 00 01 18 0F` |
| 取消去皮，17 写 2 | `01 06 00 11 00 02 58 0E` |
| 恢复出厂，19 写 12345 | `01 06 00 13 30 39 AC 1D` |

恢复出厂报文按寄存器定义生成并核算 CRC，其余报文来自说明书；均未实机执行。注意地址 18 在报文中为 `00 12`，地址 17 为 `00 11`。

### 3. 多寄存器写入：功能码 10

向地址 8～9 写入 int32 砝码重量 10000：

```text
发送：01 10 00 08 00 02 04 27 10 00 00 F9 78
```

`00 08` 为起始地址，`00 02` 为数量，`04` 为数据字节数；`27 10` 写入低字地址 8，`00 00` 写入高字地址 9。负数按 32 位补码拆分，仍为低字在前。

标准 Modbus 正常响应为以下 8 字节，不含请求的数据字节数与数据区：

```text
01 10 00 08 00 02 C0 0A
```

原文只给出 `10` 请求，未给出响应；其“所有写指令均原样回复”的说法仅由 `06` 示例支持。上述 `10` 响应按标准推导并核算 CRC，本设备实际响应需联调确认，不能直接套用请求长度接收。

## 五、编程要点

- **CRC 与接收校验**：CRC-16/MODBUS，初值 `0xFFFF`、右移多项式 `0xA001`、最终异或为 0；覆盖站地址到数据末尾，CRC 低字节先发。接收核验站地址、功能码、长度及 CRC，处理串口半包、多包合并和残帧。
- **异常响应**：按标准解析 `站号 (请求功能码 | 0x80) 异常码 CRClo CRChi`，共 5 字节；说明书未列设备具体异常码。RTU 帧间隔按标准处理，不能代替写后 500 ms 等待。
- **总线调度**：同一串口只有一个未完成请求，多设备按唯一站地址轮询；写操作暂停普通轮询，处理响应并满足写后等待再恢复。命令超时不代表未执行，校准、去皮、恢复出厂不得盲目自动重发。
- **重量读取**：只需一次读取地址 0～1，按低字在前的 int32 解析，再按标定小数位缩放。上电重量为 0 不代表已校准或无负载，通信失败不得以 0 替代有效测量值。
- **参数调整**：12、14、16、27 分别用于平均滤波、分度、采集速度和卡尔曼滤波。采集速度不等于主机轮询频率，滤波与追零会影响动态拉力；不在连接时自动去皮或改配置。
- **配置变更**：波特率下次重启生效；站地址偏移的生效时机未明确，改址应单机操作。写入前检查参数范围，不写保留地址 13，不以大范围连续写覆盖命令寄存器。
