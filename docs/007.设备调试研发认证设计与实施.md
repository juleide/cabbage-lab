# 设备调试研发认证设计与实施

日期：2026-10-31。

## 一、目标与安全边界

设备连接只允许研发人员通过用户名、密码验证后进入。未认证时只展示设备调试标题、用户名及密码表单，不读取硬件配置。普通设置、模拟试验、停止和急停不增加认证要求。

这属于本机访问控制，不是数据加密或防篡改机制。能读取本机凭据、修改应用或控制 Python 进程的本机用户仍有能力绕过限制；部署时应限制配置文件的操作系统权限。

## 二、凭据配置

```dotenv
LAB_DEVICE_DEBUG_USERNAME=
LAB_DEVICE_DEBUG_PASSWORD=
```

- 开发版：项目根目录 `.env`，同名进程环境变量覆盖文件配置；打包版：安装包内加密凭据。
- 用户名最多 256 字符，密码最多 1024 字符；精确匹配，输入不自动去空格。包含 `#` 或首尾空格的值须在 `.env` 中加引号。
- macOS/Linux 建议凭据文件权限为 `600`，Windows 应限制文件 ACL。修改后重启应用。真实凭据不使用 `VITE_` 前缀，不进入前端、日志、浏览器持久化或安装包。
- `.env` 已停止 Git 跟踪并加入忽略，本地文件仍保留，认证变量初始为空；提供 `.env.example`。本次迁移前的 `.env` 仅有导出参数，本次未创建真实凭据。
- 打包导出配置改用 `resources/config/export.env`，不再复制完整 `.env`。打包版只使用安装包内置加密凭据。
- 按部署需求更新：项目根目录 `.env` 仍由研发人员用明文维护；执行 `pnpm package` 时先生成 `resources/config/device.env.enc`，使用随机 AES-256-GCM 密钥加密两个认证值后随安装包放入 `resources/config/device.env.enc`。安装包内不含明文 `.env`。
- 打包版不再读取目标电脑 `simulation/config/.env`，也不接受外部进程环境变量覆盖，防止有本机文件权限的用户伪造账号；打包版只使用安装包内的加密凭据，凭据包带 HMAC 完整性校验，损坏或篡改会导致认证读取失败并默认拒绝访问。开发版仍使用项目根目录 `.env`，并支持进程环境变量覆盖，便于测试。

## 三、认证实现

- Electron 主进程读取配置，仅在内存持有用户名与密码摘要，分别使用 SHA-256 固定长度摘要和定时安全比较进行校验。
- 认证状态绑定主窗口 webContents ID，不接受前端提交的授权标识；硬件 RPC 转发前统一校验 `hardware.*` 权限。
- preload 仅提供状态、登录、锁定、操作续期及锁定通知接口，不返回凭据。
- 配置中的认证值不会传入 Python 子进程；启动读取后清除主进程环境中的两个凭据变量。
- 错误统一为“用户名或密码错误”；五次失败暂停 60 秒。刷新、锁定和切换窗口不会重置失败次数；重启清空内存限制。

## 四、生命周期与界面

- 验证成功进入原设备连接页，界面保持简洁，不显示单独的解锁状态栏。
- 同页切换设备类型保持认证。离开设置分类或返回试验台先确认放弃未保存修改，然后锁定；锁定失败不允许离开。
- 手动锁定有草稿时确认是否放弃；取消则保留权限与页面，确认则清除当前页面草稿。
- 闲置 15 分钟自动锁定；只读轮询认证状态不会续期，真实交互及受保护硬件请求会续期。时钟使用单调计时。
- 自动锁定通过主进程通知即时遮蔽表单，页面内草稿保留；重新验证后继续编辑，不自动保存。隐藏期间不自动加载设备配置。
- 页面刷新、窗口关闭、渲染进程退出或系统休眠均撤销认证。锁定不发送设备运动、停止、复位等指令。
- 登录支持隐藏/显示密码、Enter 提交、忙碌及限流倒计时；提交后即清空密码，失败不清空用户名。

## 六、启用步骤

1. 在开发环境根目录 `.env` 中填写上述两个变量；打包环境在应用配置目录创建 `.env`，也可以通过进程环境变量部署。

4. 不配置时保持禁用。本次仅预留空变量，没有创建默认研发账号。
