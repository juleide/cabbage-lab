# 设备连接设置页集成实施计划

日期：2026-10-31。

## 一、目标与边界

将 `docs/prototypes/device-connection-settings.html` 转换为正式 React 设置页，替换设备连接占位内容，完成配置读取、草稿保存、校验和重启恢复。保留现有主题和模拟试验行为。

现阶段 Python 只实现模拟设备，无真实串口和厂家 USB SDK。配置检查不等于硬件连接成功；不打开真实端口、不发送猜测命令，不自动运动、回零、清错、去皮或校准。不增加“待厂家确认”等配置项。

## 二、设备与配置

- 电机：固定 motor1、motor2，共用一组串口参数，各自站号，无增删。
- 升降：单台，RS232 / RS485，无站号。
- 电子皮肤：按压、抓取各一台；USB 分别绑定 REV 0～3；串口分别绑定独立端口。
- 拉力：单模块，实际站号、单位、小数位。
- 位移：单模块，P / G 类型；P 固定 CH1、原始值 0～5000；G 按实际通道及输入范围配置；支持原始值换算和 float32 结果。首次不默认 P/G。
- 独立硬件配置文件与版本，不改变试验配置格式；允许保存未完成草稿，使用前检查完整性。

## 三、实施顺序

1. 定义 TypeScript 配置类型、Python 默认值和验证规则；固定设备标识，补充位移地址选择、位移换算及拉力解析纯函数。
2. Python 增加独立硬件配置存储和 RPC：读取、保存草稿、完整检查、能力查询。原子写入，读取失败明确报错，禁止静默覆盖损坏配置。
3. 扩展现有 IPC 白名单，在设置页加入 React 设备连接组件。四个标签为概览、执行机构、电子皮肤、拉力与位移，常用项直显、高级项折叠。
4. 配置检查同时覆盖前后端；检查重复站号、重复 REV、串口占用、量程和数值范围。保存有独立加载/错误/忙碌状态，切换设置分类或返回时提醒未保存内容。
5. 能力来自后端；未实现驱动明确显示不可用，不生成假连接状态。保存不自动应用至模拟数据；真实驱动实现后使用这些配置和解析函数。
6. 测试配置读写、恢复、损坏文件、校验、换算、页面联动和保存；运行类型检查、单元测试、构建、桌面测试。

## 四、验收标准

- 页面固定两个电机、一个拉力和一个位移；无增删按钮；P/G、电子皮肤模式联动正确。
- 部分配置可保存且重启恢复；不合法的已填写值不能保存；未完成的配置不能通过完整检查。
- 后端返回明确字段路径错误；前端展示可理解错误。离线、读取失败和保存失败不伪装成成功。
- 读取失败不得用默认值直接覆盖原文件；设备配置操作不影响现有试验参数及模拟流程。
- 当前版本无真实驱动，验证按钮明确说明能力限制，不显示实机连接成功。
