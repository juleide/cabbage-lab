## 一、交付范围与结论

固定两个电机，共用一个 RS485 串口、不同站号。每台电机按已保存的方向、速度和加减速时间启动，点击关闭则停止；显示实际通信/运行状态及故障。不引入目标定位、毫米换算、完整回零、通用运动许可或轨迹编排。

建议采用串口 JOG：配置 PA_030～PA_032，写 PA_04E=0x0008 触发；关闭写 0x0020，全局软件急停写 0x0040。JOG 的串口持续运行和停止/重复启动行为必须现场验证后才能作为真实开关交付。

“关闭”不发送释放、不切断电源；初版不自动使能。开启前若状态反馈未使能，明确拒绝并提示现场检查，不暗中发送 0x0500。后续确有使能需求再单独加入明确流程，不让首次实现扩大为厂家调参工具。

**设备连接中的电机配置需要小改：保留现有共用通信配置及两个站号，新增每台电机的固定运行参数，并统一协议校验。无需重做连接页。**

## 二、配置页与配置文件改动

### 2.1 保留内容

- 共用串口、扫描、波特率、数据位/校验/停止位、超时、轮询间隔。
- 固定两个站号，无新增/删除电机，每个电机不单独选择串口。
- 草稿保存、未保存提醒、配置检查、只读验证和当前诊断状态展示。
- 保存本地文件不等于写驱动器；扫描/保存/连接验证均不得启动电机。

### 2.2 新增每台电机运行参数

在现有“设备连接 → 执行机构 → 电机”下增加两个紧凑参数组，不另建复杂运动页面：

| 建议字段 | 含义与校验 |
| --- | --- |
| direction | 正/反向，1 或 -1；机械含义现场核对 |
| speedRpm | 固定运行速度，首版使用整数，1～已配置安全上限 |
| maxSpeedRpm | 该轴已确认安全上限，整数 1～3000，不默认填 3000 |
| accelerationMs | JOG 加速时间，整数 1～2000；首版主动排除 0，不是厂家不支持 0 |
| decelerationMs | JOG 减速时间，整数 1～2000；同上 |
| maxRunMs | 单次软件运行时限，正整数毫秒，实施时定义统一有界上限并测试；不是机械保护或厂家保证 |

运行参数默认 null，允许保存不完整草稿，只读验证不要求填写；真实启动必须完整且通过校验。运行时限用于防止忘关，达到后请求停止，不做自动循环/自动续跑。软件卡死时它不可靠，不能替代有限行程保护。

不新增可随便勾选的“已安全验收所以允许启动”字段；现场验收作为交付条件，不让 JSON 的布尔值冒充物理保护。

### 2.3 推荐文件方案：扩展 hardware.json

为避免简单启停又多一个运行配置文件，推荐升级 `hardware.json` 到 schemaVersion 2：

- `motors.serial`、`motors.motor1`、`motors.motor2` 保持含义不变；后两者仍是站号，不改成对象。
- 增加 `motors.operation.motor1` / `motor2`，保存上述运行字段。
- 旧 v1 文件在内存中迁移为 v2，运行字段补 null；不自动回写原文件，更不凭迁移产生可运行默认值。
- 用户显式保存时再原子写 v2。保留损坏保护、错误提示和备份建议；旧版本程序不保证能读取 v2。
- 手动修改文件后重新启动载入；不在活动会话中热更新，保存/重启前必须停止并断开。
- 同步更新 Python defaults/validate/migration、TypeScript 类型、设置表单、配置示例及相关假串口/桌面 fixture，不能只改 UI 后被后端严格 shape 校验拒绝。

现有 `motion-safety.json` 是定位规划草稿，不作为 JOG 速度配置来源，不要求填满其毫米/脉冲字段。它的连接绑定目前散列整个 motors/lift 结构；v2 扩展可能使旧绑定失效，应显式说明并要求重新绑定，不静默改写草稿。后续如拆分连接指纹与运行指纹，必须独立版本化，不在本次顺带重构。

### 2.4 修正现有不一致

- 现 UI/HardwareStore 允许电机站号到 254，而真实会话只支持 1～247。新保存与连接检查统一为 1～247、两站不同；旧文件特殊地址不得自动改号，显示“需修改”，禁止打开真实控制。
- 电机波特率控件限定 9600/19200/38400/115200；其他设备保持各自规则。
- 电机串口组合限定原手册 PA_021 对应的 8N1/8N2/8E1/8O1，不自动写设备串口参数。
- 旧文件不支持的通信值可展示为待修正，不静默替换为某个默认值。

## 三、最小后台实现

### 3.1 复用现有串口与停止链路

复用 `devices/motion.py` 的单所有者线程、双站调度、端口互斥、取消事件、停止优先级、日志和退出处理，不另开串口/线程发送启动。

保留只读诊断入口；另增加明确的电机控制会话用途。连接本身仍只读，不自动启动。两种用途不能同时占用电机总线；升降仍只支持已有诊断，不借此开放升降动作。

### 3.2 最小接口与权限

建议新增严格的 `hardware.motor.connect/start/stop/status/disconnect`，参数只允许固定 target=motor1/motor2、会话 ID、配置版本等必要字段；速度从保存快照读取，不接受任意寄存器/原始帧。具体响应结构在实现时沿用现有会话形式，控制用途单独类型，不强改诊断的 motionAllowed:false 语义。

连接/启动沿用当前研发授权，失效时清除未发送启动并停止/关闭；查询不续期。初版真实操作不绕过研发授权，不新增通用许可 token 系统。

停止入口不要被 pending、参数不完整或未保存草稿阻塞；权限锁定后主进程已有内部停止路径必须覆盖控制会话。继续使用 JSONL 优先级与请求顺序屏障，防止先前排队的连接/启动在后续停止或锁定后又执行。

### 3.3 启动事务

1. 验证真实控制会话、当前权限/配置快照、目标状态新鲜且无故障/限位/急停、驱动已使能、该目标当前待机，以及必要现场保护条件已验收。
2. 将 `direction × speedRpm` 编为有符号单寄存器，按 PA_030～032 顺序写入速度/加速/减速，逐步检查严格匹配的写应答；最小实现可用三次受限 06，不开放任意写入。
3. 每次写之间重新检查停止/取消。准备失败或取消不发启动；停止后该次准备请求作废，下次人工启动重新完整准备。
4. 最后仅写一次 0x004E=0x0008。写超时/短写按结果未知处理，请求停止，不自动重发启动。
5. 状态字与有符号速度反馈确认进入运行；主机启动/确认等待有界，未观察到预期运行则停止并提示失败/未知，不能仅凭回显宣称开始转动。

不在运行中改速/反转；需要改参数时先停止并断开保存，再重新连接。另一电机可以独立启动，但总线事务串行，停止可抢占参数准备与反馈等待。

### 3.4 运行/停止状态

每目标只需有限状态：待机、启动中、运行中、停止中、故障/结果未知。会话状态沿用连接中/活动/断开等，不做通用运动编排。

- 普通停止只对指定电机发送；全局停止/软件急停覆盖两个已连接目标，不为停止重开未连接端口。
- 读取运行位及有符号速度判断“驱动反馈停止”；数据缺失/过期、仍运行或等待超时，保持结果未知。不显示“安全停机已确认”。
- maxRunMs 从首次可能发送启动的单调时钟起算，后台独立监督；到期停止，未知反馈也不能延长运行时限。
- 故障、软限位、过期、权限失效、退出/休眠请求停止，取消未发送启动，不自动清错、重连或续跑。
- 启停、目标站号、会话、参数版本及结果写现有运行日志；不新建复杂运动历史系统。

### 3.5 必须调整当前诊断联锁

当前检测到任意运行位即停止是只读诊断策略，不能原样用于主动运行：

- 诊断用途保持原行为。
- 控制用途仅允许处于该目标启动中/运行中时出现预期运行位；待机目标出现未授权运行，触发停止。
- 故障/限位/通信过期保护继续有效，不能为允许运行删除所有联锁。
- JOG 不依赖毫米位置，不把原始位置新鲜度或 D3 定位字段当作唯一启动条件；控制用途优先监督状态、速度与运行时限。

## 四、主界面接入与模拟隔离

为了不把真实按钮接到模拟记录上，分两个验收点：

1. 先在设备连接页现有真实设备区域增加最小真实启停控件，验收后台与现场；不改模拟开关含义。
2. 再复用同一后台接入主界面两个开关，增加明确的临时“模拟/真实电机控制”模式标识，不能仅因保存串口就自动切真实。默认模拟；模式不自动持久恢复真实动作。切换前停止/断开，控制器重启后不自动恢复真实会话。

真实主开关按实际反馈呈现，启动和停止使用明确目标状态操作，不把非幂等 toggle 简单重发。启动 pending 时可禁止重复启动，但停止始终可点击；不能沿用主面板当前 running/busy 禁用整组开关而使真实电机无法单独停止。

首期真实电机模式下禁用未实现的真实初始化/轴回零、升降模拟开关和“联动开始”，并明确说明原因；不允许真实电机运动时悄悄继续产生模拟试验数据。传感器置零按现有能力边界处理，不伪装为真实硬件置零。

“真实电机启停完成”不等于整机真实试验完成。真实采集/试验联动及结束试验自动停止两个电机留作独立批次；本批次既不混合数据，也不顺带改现有模拟结束语义。

测试重点：

- v1→v2、损坏文件、非法数/布尔值、范围、未知字段、外部编辑重启、未保存草稿、活动会话配置互锁及旧安全绑定失效。
- 正反 JOG 编码；每个写应答的站号/功能码/地址/值/CRC；异常应答、超时、短写、局部准备成功后失败不启动。
- 停止在三次参数写入、触发前后、状态/速度等待各阶段抢占；另一电机请求不造成停止饥饿；旧请求在锁定/停止后不得复活。
- 重复点击、驱动未使能、运行未确认、停止未确认、运行时限、故障/限位/反馈过期、OS 打开/关闭阻塞、不自动重连。
- 桌面验证固定两台/一个端口、参数持久化、真实与模拟隔离、运行状态展示、停止不被 busy 禁用；旧配置/诊断/传感器/模拟试验全回归。

## 六、现场待提供的最少信息

每轴用途及是否有限行程、实际 CL/OL 型号和工作方式、当前使能方式、正反方向、安全速度、加减速、最长允许连续运行时间、有效限位/独立急停/断线保护、停止后的保持行为。通过厂家工具读取实物参数，不复制手册示例。

对于有限行程轴：确认驱动软限位仅回零后生效；若依赖它则真实回零不是可省项。首期若没有已验收的行程保护，不开放持续 JOG，可先完成软件与假串口交付，等待现场条件。

## 七、最终交付边界

完成后应能做到：配置文件保存两个电机的连接及固定运行参数，逐台真实启动/停止、展示驱动反馈，异常不自动续跑，原模拟功能保持隔离。

不承诺：机械定位、自动回零、同步轨迹、升降真实运动、真实整机试验、或通信故障时软件一定能停住机构。实施中不增加与最小启停无关的复杂功能。
