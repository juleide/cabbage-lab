# 内置控制端构建与验证记录

## 范围与当前结论

- 目标：Windows x64 安装包携带 onedir 独立控制端；最终用户不安装 Python 或 pyserial。
- 本次仅修改入口、构建、资源分发及 Electron 控制进程启动方式，不修改公共 IPC、共享类型、硬件协议、硬件配置结构或业务页面。
- 保留现有自动连接、无有效读数显示 0、设备未就绪限制操作等逻辑。独立打包不补齐未实现的硬件功能。
- **当前不是正式交付就绪状态。** 独立产物构建受依赖下载条件限制，Windows 安装和真实硬件验收尚未执行。

## 构建约定

- 轻量入口：`backend/controller-entry.py`，只配置 JSONL 所需的 UTF-8 标准流并调用现有 `lab_controller.__main__.main()`。
- 依赖：运行依赖 `backend/requirements.txt`；构建依赖 `backend/requirements-build.txt`，PyInstaller 固定为 6.16.0。
- 解释器：显式 `LAB_PYTHON` 优先，否则项目 `.venv`、`backend/.venv`、系统 Python；选择后依赖缺失直接停止，不换解释器掩盖问题，也不自动安装依赖。
- 每次构建清理 `dist/controller/` 和 `dist/controller-build/`；不清理其他应用或安装包目录。构建虚拟环境、产物均不进入 Git。
- 控制端为 `dist/controller/lab-controller/` 完整目录，安装到 `resources/controller/`。必须连同 `_internal/` 分发，不能只复制 exe。
- `pnpm package` 串联类型检查、应用构建、控制端构建、安全通信检查、原有配置资源准备和安装包生成，失败即停。
- electron-builder 的 beforePack / afterPack 校验本机与目标平台/架构一致、构建标记、可执行文件和 `_internal/` 目录存在。不支持跨平台、跨架构或 universal 混装。
- 安装环境固定启动内置程序，清除开发 Python 路径相关环境，不回退系统 Python；开发环境继续模块启动。
- 不复制 `hardware.json`、本机用户数据或源码进入安装资源；其余原有配置、授权资源、图标准备流程不变。

## 依赖恢复后的本机检查

```sh
.venv/bin/python -m pip install -r backend/requirements-build.txt
pnpm controller:build
pnpm controller:check
pnpm package
```

`controller:check` 会把完整独立控制端复制到中文/空格临时资源路径，以全新数据目录检查 ready、ping、shutdown 和正常退出；清除 `LAB_PYTHON`、`PYTHONPATH`、`PYTHONHOME`，不发送运动指令。失败时终止并等待子进程关闭，然后清理临时目录。成功检查也不能替代 Windows 安装和硬件验收。
