# 电机最小控制需求评估

日期：2026-11-01。范围：先依据厂家原始资料补齐协议文档，再按当前项目代码评估最小电机控制需求；本轮不修改控制代码、不开放真实运动。

具体配置结构、后台启停流程、主界面接入与验收批次见 [电机最小启停实施计划](012.电机最小启停实施计划.md)。

## 一、结论

**当前项目适合先做“两个固定电机的独立启动/停止 + 固定运行参数 + 基本状态/故障反馈”，不需要先做完整定位、轨迹规划、复杂许可系统或厂家全功能调参界面。**

这里的开启建议解释为“按保存方向和速度运行”，关闭解释为“停止运行，保持力行为现场确认”；不是切断电源，也不默认发送使能/释放。现有代码的日志和试验前置条件支持“运行/停止”的产品解释，但模拟布尔值本身不能证明现场电机用途或运动方式，最终仍需核对两轴机械角色。

原手册已经补齐定位、JOG、回零、方向和限位的关键协议定义。不能继续把“电机运动参数映射未知”作为所有开发的笼统阻塞；也不能反过来把厂家提供的全部功能都变为本项目必做需求。

## 二、当前项目实际提供了什么

| 证据 | 当前实际行为 | 对需求的含义 |
| --- | --- | --- |
| `src/renderer/src/components/DeviceControlPanel.tsx` | 1、2 号电机各一个开关，无目标位置、圈数、速度或轨迹输入 | 首期应保持简单启停界面 |
| `backend/src/lab_controller/core/controller.py` 的 toggle | 翻转模拟输出，日志称启动/停止 | 当前不是硬件使能、释放或运动帧 |
| 同文件的 run | 两个模拟电机开关都开后才能开始记录；结束试验仅结束记录状态，并未自动关闭电机 | “联动”目前不是多轴同步运动控制，真实接入需明确结束是否同时停机 |
| `backend/src/lab_controller/devices/simulated.py` | 输出是布尔值；速度是模拟公式，不来自驱动 | 不能从模拟的 10 mm/s 推导现场 rpm、传动比或机械角色 |
| 同界面的初始化/轴回零 | 初始化清模拟输出并恢复气压等；回零仅记录模拟完成消息 | 按钮存在不代表首期必须实现真实回零，不能自动把初始化变为回零/清错 |
| `devices/motion.py` 与 MotionConnections | 独立真实只读诊断、受限停止和后台联锁；不接主开关 | 复用端口所有权、调度、停止、状态等基础，不把主开关直接映射到诊断连接 |

项目只将设备称为“1 号/2 号电机”，没有代码依据确认哪台拖动、哪台进给，也没有已确认的无限旋转/有限行程定义。UI 有“水平拖动速度”，但它目前是模拟指标，不能据此认定两个电机都适合无限连续旋转。

## 三、首期建议实现范围

### 3.1 操作界面保持简单

- 主界面继续保留每个电机一个启动/停止开关，不新增定位面板、回零向导、运动预演必填步骤或多层确认流程。
- 开关状态依据反馈表达未连接、待机、启动中、运行中、停止中、故障/结果未知，不能收到写应答就立即标为运行成功。
- 运行参数只放设置中，保存到配置文件，允许备份后手动修改并重启载入；不在本轮决定新文件/schema，更不把连接 hardware.json 的当前字段当作已有速度字段。
- 不删除现有安全草稿/离线计算功能，但不把其定位字段全填满作为“仅速度启停”的必备步骤。后续按操作校验所需参数，保留已确认的现场保护条件。

### 3.2 最少配置

两个电机仍共用串口，各自唯一站号，连接配置沿用既有实现。每台电机另需明确：

| 参数 | 必要性 |
| --- | --- |
| 实物型号/开闭环工作方式 | 首次验收记录，决定位置读数含义；不必增加复杂型号选择界面 |
| 运行方向 | 现场确认，不从电机编号猜测 |
| 固定运行速度 r/min | 开启后有明确速度；正数大小与方向分开表达，内部可编码为有符号 JOG 速度 |
| 加速/减速时间 ms | 使用保守、现场验证值，不因协议允许 0 就默认 0 |
| 实际安全速度上限 | 不直接以驱动 3000 rpm 上限作为本机允许值 |
| 连续旋转还是有限行程 | 决定能否直接持续运行及必须具备何种行程保护 |

有限行程机构必须确认有效限位/独立保护；若现场不能保证，不能使用无边界的持续运行。可以选择更小的有界动作或补齐行程保护，而不是一开始开发通用定位系统。

### 3.3 候选执行方式：固定速度 JOG

原手册已明确 PA_030 的有符号速度、PA_031/032 的加减速时间，以及 PA_04E Bit3 触发 JOG。若现场确认需要“开后持续运动，关后停止”，它比设置目标位置更贴近当前界面需求：

1. 开启前确认连接、无故障、当前状态可接受且必要行程保护有效。
2. 写入该电机固定 JOG 参数，严格检查应答；参数准备失败不发送启动。
3. 按需要处理已确认的使能状态，再触发 JOG；不要默认每次开关都使能/释放。
4. 读取运行状态/速度反馈，失败显示未知并请求停止，不自动重发启动。
5. 关闭发送普通停止；全局急停使用已知软件急停并提示现场硬急停，不把释放当停止。

这是候选方案，不是已实机验证的结论。还需验证串口 JOG 的持续性、重复启动、停止及重新启动行为。不要改写 DI 功能或常开常闭配置模拟按钮，不自动保存驱动参数到非易失存储。

若确认“开启”仅指通电保持而不转动，应改为使能/保持需求，不采用 JOG；如果轴需要按固定距离移动，则采用小范围定位功能，而不是强行持续转动。现有模拟代码无法最终裁定这些物理含义。

## 四、必须保留的少量控制保障

简单按钮不等于只发送一帧后就不管：

- 复用一个串口所有者和双站串行调度，防止响应串台；停止优先，不堆积重复启动。
- 启动参数/方向/速度校验、故障/急停状态禁止启动，断线不自动恢复运行。
- 周期读取状态，数据过期显示不可用；启停写超时保持结果未知，不盲目重发。
- 明确权限锁定、退出、休眠和断开时请求停止；通信失败不能承诺停止送达，现场必须具备独立安全措施。
- 确认行程/硬限位及停止保持方式，尤其释放后是否可能滑动、下落。
- 真实试验结束与全局停止建议停止两个试验电机；改行为前写入验收用例，不沿用“只停记录”的模拟逻辑而不说明。

这些用现有会话、队列、状态和错误处理可以增量完成，不必先开发通用短时 token、运动编排或多轴轨迹系统。

## 五、可暂缓的内容

| 功能 | 首期处理 |
| --- | --- |
| 绝对/相对定位、目标毫米、任意圈数 | 暂缓，除非机械动作本身需要 |
| 多段路径、同步插补、轨迹规划 | 不做，当前无明确需求 |
| 完整回零模式和任意 DI/DO 参数编辑 | 暂缓；主界面真实回零禁用并说明，不伪报完成 |
| 每次启动前填写全套定位安全草稿 | 不作为速度启停流程；只校验对应操作真正需要的条件 |
| 自动修改电流、细分、方向参数、清错、恢复出厂/保存参数 | 不做，首次由厂家工具核验，应用不自动覆盖 |
| 释放/断电控制 | 不把它作为“关闭”的默认含义 |
| 开环位置当实际机械位置 | 禁止；必要实测位置另由传感器/机构设计解决 |

回零和毫米换算只在具体轴的工艺/行程保护确实依赖时提升优先级，不因为驱动器支持就全部实现。驱动软限位仅回零后生效，不能一边依赖它、一边把回零当作无条件可省略。

## 六、现有程序需要处理的实际差距

1. 主开关仍是模拟，需增加明确的真实控制接入，不允许只改前端布尔值冒充硬件动作。
2. 现有诊断模式检测到运行位会触发停止。将来正常主动运行必须和只读诊断区分，保留故障/限位保护，不能简单把全部联锁删除。
3. 模拟试验和真实传感器/运动诊断目前保守互斥。首期先验收独立真实电机启停，整机试验再单独接入，不宣称打开真实电机后现有“联动开始”就能记录真实数据。
4. 原始位置当前保留无符号位值，这是旧资料不全时的保守实现；原手册现已明确 int32，后续可补有符号脉冲显示，无需为了启停先做毫米定位。
5. 当前轴回零和初始化仍是模拟；真实模式禁用未实现动作，初始化不暗中移动或清错。

## 七、最小实施与验收顺序

1. 文档补齐：本轮已完成参数/符号/限位/歧义及需求收缩记录，没有改运行代码。
2. 现场确认最少信息：两个轴各自用途、运行方式、方向、速度、加减速、有效限位/独立保护和关闭后的保持行为；用厂家软件读取实际配置，不套用示例。
3. 单设备最小启停：复用现有后台，增加固定参数 JOG 与按目标停止，不开放任意寄存器；先假串口覆盖参数写失败、启动未知、重复点击、停止优先和故障处理。
4. 人工监护下逐台验证低速启停，然后同总线验证两台互不串台、断线/限位/急停和退出处理。
5. 独立启停通过后，再按真实试验需求接入主界面/采集协调；不顺带扩展整套定位/回零产品。

验收以“两个电机各自按明确参数启动，关闭能请求停止，反馈不造假，异常不自动续跑”为首期目标。机械停止仍须实测，软件状态不替代硬件安全。

**最终结论：缩小范围做实际需要的启停，不把完整电机驱动器功能搬进项目。协议已补齐的内容作为实现依据和后续储备；首期只取固定参数启停所需部分。**
