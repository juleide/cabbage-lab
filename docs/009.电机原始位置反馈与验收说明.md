## 一、范围与协议依据

本批次先完成下一阶段可依据现有资料实现的只读位置反馈，不开放真实电机启动、使能、释放、回零或升降运动，不创建运动许可。

依据 [57 步进电机接入说明](控制协议/57步进电机-力川RS485驱动接入说明.md) 第 2、9.2、10 节：当前位置高字/低字位于 `0x0008/0x0009`，使用功能码 03，从地址 8 连续读取两个寄存器，高字在前。该资料仍是用户协议总结，未再次核对厂家原始手册，实机兼容性需另行验收。

离线向量（站号 1）：

```text
请求：01 03 00 08 00 02 45 C9
响应：01 03 04 00 00 13 88 F7 65
原始位值：0x00001388，即十进制 5000
```

`5000` 的展示不是 5000 mm；没有确认符号、脉冲标定和机械零点前，不从这个值生成物理位置。`0xFFFFFFFF` 展示为 4294967295，不自行解释成 -1；D3 保守非负 31 位离线目标限制不用于截断真实读取的 32 位原始信息。

## 二、轮询与资源所有权

- 固定两个电机共用一个串口，单个后台所有者线程按 `motor1 状态 → motor1 位置 → motor2 状态 → motor2 位置` 顺序完成一个轮询周期。
- 状态单独读取 `0x0004` 一个寄存器；位置一次读取 `0x0008` 起两个寄存器，不分两次请求、不跨越未定义寄存器合并查询。
- 轮询周期完成后等待连接配置的 `intervalMs`；实际更新周期还包含总线静默间隔、设备响应和事务耗时，不保证等于 `intervalMs`。
- 连接只增加已定义的 03 查询，不发送运动或辅助控制；未连接时不读取位置，不增加自动扫描、自动重连或额外串口。
- 不读取当前速度：本批次仅解决位置位值，速度符号、方向与运动许可使用条件留待协议核验。
- 升降与传感器逻辑、共享资源互斥规则不变。主试验仍为模拟，不把诊断位置写入模拟曲线、速度、CSV 或真实试验结果。

## 三、状态接口

沿用 `hardware.motion.status`，无需新增 RPC 或配置字段。每个电机的 `readings.motor1/2` 原状态字段保持不变，按收到位置的情况增加可选 `position`：

| 字段 | 说明 |
| --- | --- |
| `highWord` / `lowWord` | 原始高、低 uint16 寄存器 |
| `rawUnsigned` | `(highWord << 16) | lowWord`，0～4294967295 |
| `interpretationVerified` | 固定 false，不能通过配置文件变成 true |
| `receivedAt` | 主机完成接收位置响应的时间，秒；不是设备采样时间 |
| `ageMs` | 用单调时钟计算的位置接收年龄 |
| `quality` | valid 或 stale，仅描述通信数据新鲜度，不表示可授权运动 |

没有成功收到完整位置响应前，`position` 不存在，不能以 0 补齐。RPC 轮询界面展示原始十进制位值及高低字；位置过期、会话非 monitoring 或连接状态未知时，不展示旧值为当前位置。

状态字与位置拥有独立的接收时钟。刷新状态不会刷新位置；收到位置也不会刷新状态字。两者采用既有 `max(1000, 3 × intervalMs)` 毫秒诊断阈值，而不是 D3 草稿时限。阈值仅为主机显示策略，不是设备安全保证。

两次响应并非同一时刻采样，高低字一次读取也不证明从机内部具有原子快照/锁存功能。数据可用于观察通信，不得据此推导机械已停、速度为零或到位精度。

## 四、停止优先与故障处理

1. 每次位置查询经过既有 RTU 帧校验：匹配站号、功能码、字节数、CRC，处理异常响应。只有完整、匹配的响应才解码位置。
2. 状态读取完成后优先检查停止请求；已检测故障并入队的软件急停不必先等待位置读取。
3. 位置等待使用同一个可取消只读总线。停止/断开可以打断等待，取消或不完整的响应不发布位置。后续停止仍走 D2 有界优先队列和单次发送策略。
4. 位置超时、错误响应或串口错误沿用既有诊断失败策略：故障锁存、所有反馈失效、结束会话、关闭端口，不自动重试或重连。旧位置即使刚收到，也会在失败/关闭期间标为 stale。
5. 通信故障结束不保证另发停止能送达；关闭串口不是机械停止。停止 ACK 仍只表示回显，不表示机械停止。必须使用独立硬急停和断线保护。
6. 普通 Python 线程不能保证系统串口打开/关闭阻塞时的实时性。UI 依赖状态轮询与 IPC，不能担当硬实时联锁。
7. Modbus 03 响应不携带寄存器地址和事务号。站号与长度相同的迟到响应不能仅凭协议字段完全区分；适配器回显、帧间隔、异常延迟、驱动内部一致性仍需实机核验。不得以通过假串口测试替代此验收。

本批次没有新增基于位置的自动停机、已停判定或到位判定。用未经核验的单位和符号驱动这些判断会产生错误安全结论。

## 五、能力评估的变化

- 缺少或过期原始位置时，继续显示 `POSITION_UNAVAILABLE`。
- 读到新鲜原始位置后，不再显示“尚未采集位置”，但仍固定显示 `POSITION_INTERPRETATION_UNVERIFIED`。
- D3 的执行未开放、设备身份未核验、材料未经核验、运动协议缺项等阻断保留；所有目标 `canExecute` 仍为 false。
- 离线规划保持人工输入起点，不自动带入原始位置，也不自动把原始位置按草稿标定转换为真实位置。

## 六、测试与现场验收

自动测试不访问实物端口：

```sh
python3 scripts/motion-protocol-test.py
python3 scripts/hardware-motion-test.py
python3 scripts/motion-safety-test.py
pnpm build
pnpm exec playwright test tests/desktop/motion.spec.ts
```

覆盖高低字顺序、32 位边界、非法类型、协议向量、双站串行顺序、独立新鲜度、快照副本隔离、位置读取超时、错误站号/字节数/CRC/异常响应、位置等待期间急停、失败时旧位置失效，以及真实 Electron IPC → Python → 假串口读取和锁定停止链路。界面测试检查过期位置隐藏，同时状态字仍能保持有效。所有这些测试均不证明真实设备动作或保护行为。

现场只读验收顺序：

1. 核对驱动型号/版本、厂家原始寄存器手册、拨码站号、接线、终端电阻和串口参数；准备硬急停与独立人员监护。
2. 先在设备不允许运动的受控状态下连接诊断，确认只出现 03 查询，两个站号均对应正确设备。
3. 将程序高低字与厂家工具比对，记录正负位置、跨 16 位边界、零点及掉电后的读数行为；未核验前不得依靠程序换算位置。
4. 确认从机读两个位置寄存器时的锁存一致性、响应周期、适配器回显和迟到帧行为；确认增加查询负载后状态更新满足实际要求。
5. 验证拔线/断电/错误应答显示不可用、不自动重连，使用独立措施确认机械安全；不能把关闭端口作为停机验收。
6. 形成可追溯的记录，再决定位置符号、标定和运行时使用策略。

后续 D4b 仍需协议字段补齐、设备身份及现场证据核验，然后才能设计可信物理位置、运行时安全状态机、短时会话许可、停止确认和故障联锁。缺少这些输入时，程序继续禁用真实运动。
