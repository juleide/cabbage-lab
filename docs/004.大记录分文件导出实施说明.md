# 大记录分文件导出

## 目标与配置

对单次试验的 CSV 导出自动分卷，不改变数据内容或数据库结构。首页和历史记录页共用同一逻辑。

- 项目根目录 `.env` 已配置 `LAB_EXPORT_MAX_ROWS=5000`，可直接编辑。
- 未设置时默认 **5000 条采样记录／文件**，便于初次调试，表头不计入。
- 接受正的十进制安全整数，可设置 `500000` 用于较大的分卷。空值、零、负数、小数和非数字在导出时明确报错。
- 每次导出开始时读取一次配置：系统环境变量优先于文件，文件缺失或未设置键时回退到内置默认值。修改文件对下一次导出生效，不影响进行中的任务。
- 开发读取根目录 `.env`；打包将其复制到资源目录 `config/export.env`，安装后的应用读取该文件。仅读取导出阈值，不加载其他键，不在该文件存放敏感信息。

## 行为

1. 固定试验编号和采样快照总数，后续新采样不计入本次导出。
2. 记录数不超过阈值时，保留原有单 CSV 保存对话框。
3. 超过阈值时，确认记录数及分卷数，再选择保存父目录。
4. 在父目录中创建临时目录，逐卷写入。每卷包括 BOM、表头、相同列顺序和精度，最后一卷保存余数，不生成空文件。
5. 文件名为 `<runId>-part001.csv` 等，序号最少三位。全部同步并关闭后，将临时目录重命名为 `<runId>-export-<时间>-<UUID>`。
6. 不覆盖已有导出目录。失败时关闭文件、删除本次临时目录；清理失败也会报告临时路径，原始数据库不变。

## 实现

- 主进程将保存位置选择、临时目录及最终发布与可复用分页写入器分离。
- 每页最多 250 条，并受当前分卷剩余容量限制；每批完整写入后才推进偏移。
- 使用 FileHandle.writeFile 顺序写入，避免单次 write 短写导致缺失内容。内存不随总记录数增长。
- 返回结果保留 saved／count，增加 fileCount、outputPath、outputKind，前端区分单文件和目录成功提示。
- Python 的 records.snapshot／records.read、CSV 字段、SQLite 结构、重复导出限制和重启互锁不变。

## 检查与边界

复用既有轻量检查，通过小阈值确认等于阈值、阈值加一、整数倍、余数卷、250 条分页边界、BOM／表头、完整顺序、无后续采样混入及读取失败关闭文件。另做类型检查与构建，不创建海量数据或长时间压力测试。

本轮不添加进度条、运行中取消、时间筛选、数据库查询超时调整或额外保存格式。磁盘不足、权限、文件占用及控制端断开仍可能导致失败。强退可能遗留临时文件或目录，不将临时结果标为成功；原生保存／目录对话框需在本机实际操作确认。
