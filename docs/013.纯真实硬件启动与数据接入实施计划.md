## 一、决策与替代关系

根据最新要求，生产程序完全移除模拟模式。本文替代 `012.电机最小启停实施计划.md` 中保留模拟试验、增加模拟/真实模式切换的过渡方案。012 中受限 JOG、停止优先、单串口所有权、故障处理等已实现能力继续复用，不回退用户配置与历史记录。

目标：程序启动即按生效配置连接真实硬件，不要求先进入设备连接页，不设置整机配置完整性前置关卡。所有数值必须来自真实读数或有明确依据的真实数据计算；未连接、未读取、失效和过期显示 0。自动连接不自动运动。

参考项目 `/Users/yh/project/code` 自动启动串口和接收线程的流程，不照搬其硬编码端口、异常吞掉、故障代用值或上电旋转杯复位。

## 二、运行规则

### 2.1 数据显示

| 情况 | 数值 | 数据状态 |
| --- | --- | --- |
| 启动后尚无读数 | 0 | 等待数据 |
| 未连接或打开失败 | 0 | 未连接 |
| 已打开但无有效反馈 | 0 | 等待数据 |
| 有效且新鲜的硬件读数 | 实际值 | 正常 |
| 断线、无效、读取失败或过期 | 0 | 数据不可用 |

各项数据独立更新，不因另一设备缺失而清零已有有效读数。零占位和有效的真实零值必须通过质量/来源字段区分，零占位不能写为正常样本。设置页可展示原始反馈、错误和更新时间，首页不保留过期旧值。

压力阵列无有效帧时显示全零初始网格，不生成随机波形、演示图案或备用帧。派生指标只能由有效真实输入计算，缺少输入或换算依据时为 0 并标记不可用。

### 2.2 启动与连接

流程：内置默认值加载并叠加保存配置 → 界面零初值显示 → 后台立即逐设备连接 → 接收/轮询反馈 → 更新真实数值和设备状态。

- 不先要求所有字段填写完整，不因一台设备失败阻止其他设备连接。
- 无配置文件时生成完整默认文件并尝试连接。已有配置保留用户值，缺失字段补默认值；空白旧字段的补值规则需显式版本迁移和测试，不静默替换非空的错误端口/站号。
- 文件损坏时保留原文件，显示错误，本次可使用默认配置尝试连接；不覆盖损坏文件，显式修复保存保留现有保护流程。
- 必须保留单设备必要的类型、编码和范围校验，拒绝危险/非法请求；这不是整机启动前的完整性审批。
- 打开失败、协议异常明确归属对应设备；界面保持可用，相关数值为 0。
- 首期提供人工逐设备/统一重新连接，不无限自动重连；重连不恢复运动或试验。
- 初始自动连接只读：不自动启动、使能、清错、释放、回零、升降或恢复上次动作。

### 2.3 默认配置

配置页不再以空白字段作为首次使用入口。所有连接参数使用可见默认值，界面值与后台生效快照一致。

| 部分 | 默认策略 |
| --- | --- |
| 串口 | 按目标电脑端口分配表给出完整默认值，可修改，不声称端口来自协议 |
| 通信格式 | 按各设备手册填波特率、数据位、校验和停止位 |
| 超时/轮询 | 使用有界默认值，标明本地主机策略 |
| 电机 | 固定站号 1/2，共用串口；运行参数为明确标注的初始调试值，不代表已实机验收 |
| 升降 | 当前已知 RS232 38400/8N1；不得猜测 RS485 协议 |
| 拉力/位移 | 补齐站号、型号、通道、读取方式；未有标定依据时保留原始单位，不冒充工程量 |
| 电子皮肤 | 遵循 USB REV 或逐采集器独立串口规则，不能凭空猜测 USB 驱动/API |

保持 AGENTS.md：两台电机固定且同总线；不同设备类型分配不同串口；拉力/位移各一个模块；电子皮肤 USB 使用 REV 0～3、串口模式逐采集器独立绑定。

默认值与“已核验安全值/标定值”分开表述。协议上限不等于本机安全上限，厂家示例不等于现场标定。

### 2.4 就绪与权限

右上角：设备连接中 → 设备未就绪 → 设备已就绪；故障/反馈过期时为设备异常。配置读取错误另给明确提示，不将 Python 在线、端口打开或默认字段非空当作就绪。

必需设备取得有效反馈并满足各自待机条件后才就绪。按机型定义必需设备清单，不自动忽略失败设备以凑成就绪；尚无可靠反馈协议的设备不能伪造就绪。

自动只读连接和显示不依赖进入研发页面。配置/诊断权限与运行权限分离梳理；不得为自动连接开放任意写入。停止始终可用，普通 busy、草稿、权限失效不能阻塞停止。

## 三、实施批次

### A：真实数据基础与移除模拟路径

1. 梳理首页所有值的真实来源，形成来源/单位/标定/换算表。
2. 移除生产入口对 SimulatedDevice 的依赖、模拟参数定时生成和模拟输出布尔控制。
3. 移除模拟阵列发生器，保留零初始网格与真实帧入口。
4. 删除 motorMode、模式切换接口及首页选择入口。
5. 删除模拟初始化/回零的成功响应；未实现功能明确禁用。
6. 假串口/构造数据只留测试，不作为产品模式。

验收：无设备时长期保持零值，无随机变化、不新增试验采样。初始/无效零与有效真实零可区分。

### B：默认配置与启动连接

1. 更新 Python 默认值、类型、配置示例与设置表单，落实旧配置迁移。
2. 后台启动时发起逐设备连接，异步处理打开/读取，不阻塞界面。
3. 单一串口所有者复用控制/采集/诊断，配置页不再重复打开相同设备。
4. 改造现有诊断、只读验证、传感器和运动互斥策略，使真实设备可在各自端口并存，不简单删除互斥保护。
5. 改配置前先停止并关闭受影响连接，重连应用新快照；不恢复动作。
6. 独立错误、状态、超时和手动重连入口。

验收：无文件首次启动生成默认配置并逐设备尝试；一个端口失败不影响其他设备；打开不引起机械运动；损坏/旧文件不会被静默覆盖。

### C：真实读数、阵列和派生值

| 指标 | 依据 |
| --- | --- |
| 拉力/位移 | 复用真实采集驱动，确认通道映射和单位 |
| 电机状态/转速 | 复用状态字和有符号速度，不把 rpm 当 mm/s |
| 压力阵列 | 对接真实采集卡，缺帧/过期为零初始网格 |
| 接触面积 | 有效阵列、阈值、单元面积均明确后计算 |
| 水平速度 | 真实位移与单调时间差，或已确认传动换算 |
| 摩擦系数 | 对应真实力值，分母有效，输入时效满足要求 |
| 气压/其他 | 无反馈通道则 0+不可用，不将设定值冒充实测 |

后台维护数值、来源、质量和单调接收时间。读数失效/过期清零，不从旧 lastValid 回填。真实数据到达后逐项更新，不等待整机所有数据齐全。

### D：首页真实控制与状态

1. 移除模拟标识和切换入口，电机开关直接接真实控制。
2. 初始为 0；每项按质量显示，右上角依据设备反馈汇总。
3. 复用 JOG 受限事务、取消屏障和后台运行时限；不自动使能或运动。
4. 停止在连接/准备/运行/断开期间保持入口可用。
5. 初始化只执行明确的真实检查，不偷偷移动；回零、升降等未实现动作禁用并说明。
6. 联动记录条件不满足时禁用并给出缺失设备/数据原因。

### E：真实试验记录

1. 仅接受真实有效输入，不保存占位零为正常样本。
2. 条件不足拒绝开始；运行中必要数据失效则终止并记录原因，不以零补样。
3. 记录结束与电机停止分开报告，均不得冒充机械安全已确认。
4. 历史记录不删除。先核对来源能否可靠识别，再标记/归档；无法识别的不声称真实。

### F：回归与现场

- 无文件、旧文件、损坏文件、非法参数、端口冲突和设置页生效值一致性。
- 无硬件启动为零；部分失败其余仍采集；首份反馈与过期清零；有效真实零可记录、占位零不可记录。
- 自动打开串口无运动写；重复连接、配置更改、退出/休眠、阻塞驱动和停止优先。
- 无模拟波形/云图/采样；真实阵列拆包/CRC/重排和标定计算验证。
- 真实电机启停、运行中断线、记录终止与停止结果分别验证；无自动恢复动作。
- 实际 Electron→Python→假串口链路、界面截图及回归。
- 最后执行实物低速、单设备、全设备、限位、独立急停/断线测试。假串口不能替代现场验收。

## 四、执行顺序与边界

真实来源梳理与零值数据模型 → 移除模拟源 → 默认配置与自动连接 → 真实数据显示 → 首页控制 → 真实记录 → 回归与实物验收。

当前电机、部分传感器有真实驱动基础；真实压力阵列、升降动作和整机采集联动未全部完成。缺协议、驱动或标定时保留 0 和具体不可用原因，不用假值填补，也不将删除“模拟”文字当作硬件接入完成。
