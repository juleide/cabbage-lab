# 保持首页结构的真实硬件接入实施计划

日期：2026-11-01。

本文是 013《纯真实硬件启动与数据接入实施计划》的执行修订版。保留 013 中纯真实数据、启动自动连接、配置持久化、停止保护等要求；后续按本文顺序实施。012 中模拟/真实模式并存方案不恢复。

## 一、本轮决定

1. 首页恢复原有结构，不重新设计页面。保留三组设备开关、夹爪气压控制区、初始化/回零/置零、联动入口、八项实时参数、云图及记录区域。
2. 撤掉首页新增的真实电机连接区、研发登录表单、模式说明区、额外停止按钮及其专用样式。不要再把设备连接设置搬到首页。
3. 不提供模拟/真实切换，不增加首页“真实硬件模式”标识。首页只需原有右上角设备状态。
4. 回退的是首页结构，不恢复模拟数据、模拟动作成功响应、模拟阵列或抓取面积/抓取力的固定比例换算。
5. 界面回退轮次只回退界面并修订计划；后续已按用户新指令开始实施，进度见第七节。当前后端仍非现场验收版本。

## 二、最终行为

### 2.1 程序启动

加载默认配置与已保存配置 → 首页参数为 0 → 后台逐设备打开配置中的端口并接收/轮询数据 → 更新真实读数和状态。

- 不要求先进入设置页，不需要点击首页“连接真实电机”。
- 不先做整机字段完整性审批，不因一台设备失败阻止其他独立设备连接。
- 保留驱动必要的类型、范围、站号、端口冲突和报文校验；非法配置只影响对应设备。
- 自动连接仅打开通信和读取反馈，绝不自动启动、使能、回零、清故障或恢复上次动作。
- 读取配置文件失败或设备打开失败要记录明确错误，不能吞掉异常后显示“设备已就绪”。

### 2.2 首页

| 原有区域 | 后续修改范围 |
| --- | --- |
| 1/2 号电机开关 | 位置与样式不变；连接后台已有的真实 JOG/停止控制 |
| 升降装置开关 | 位置与样式不变；驱动未接入时禁用，不返回虚假启动成功 |
| 气压控制区 | 结构不变；设定值与实测值分开处理，无真实设定接口时禁用写入 |
| 初始化/回零/置零 | 不移动、不新增面板；未实现动作禁用，原因使用原有提示或 title |
| 联动入口 | 保留；真实记录条件不满足时禁用，不创建占位试验 |
| 八项实时参数 | 全部保留；逐项读取真实值，缺失为 0，不删卡片、不用比例凑数 |
| 压力云图 | 原布局不变；未收到有效真实帧时为零初始网格，不保留过期图案 |
| 右上状态 | 连接中/未就绪/已就绪/异常；急停和离线状态优先 |

Python 在线、配置非空或串口打开都不能单独等于“设备已就绪”。

### 2.3 配置与设置页

- `config/hardware.json` 是硬件配置的唯一来源；设置页保存后写入该文件，手动修改文件后重启加载。
- 初次启动生成默认文件；默认参数在设置页可见，不仅存在于前端输入框占位提示中。
- 已有合法配置保留原值；缺字段补默认值，版本迁移明确记录；损坏文件不静默覆盖。
- 修改配置后按受影响设备停止、关闭、应用新快照、重新连接；不会恢复原运动。
- 串口扫描只枚举端口，不把扫描顺序当作设备身份，不自动轮询所有串口来猜设备。

## 三、执行前基线与必须纠正的问题

本节记录本轮开发前的风险，后续完成状态见第七节，不应把这里列出的旧问题当作始终未修正。

当前代码只具备局部成果，并非已完成纯真实化：

- Controller 已不再创建 `SimulatedDevice`，阵列已不再生成合成帧，真实读数类已有缺失/过期清零基础。
- 模式字段及模式切换 RPC 已从生产协议移除；电机 JOG/停止保护等既有真实驱动继续复用。
- 最近加入了按配置启动传感器/电机连接的入口，但缺少针对完整启动链的回归，不能视为 B 批次验收通过。
- 自动连接当前仍依赖 `complete=True`，可能因电机运行参数未填写而阻止只读连接；需拆开连接所需参数与启动所需参数。
- 自动连接与手动连接存在重复的会话启动/记录逻辑；失败清理、跨管理器端口归属、互斥和重连尚未统一。
- 当前将单位为 N 的拉力直接写入 `normal`，以及由位移差写入首页水平速度，缺少机械角色映射依据。不能只凭单位就认定这是法向力或水平轴，必须先纠正。
- `refresh()` 将设备状态一律置为 false，不是真实反馈状态；右上就绪汇总尚未实现。
- 当前通用命令保护过宽，可能连记录库切换等非运动操作一起拒绝；需要逐命令分流。
- 首页已按本轮要求恢复原结构，但恢复后的原有控件尚未全部与新后端契约接通。不能用界面恢复宣称功能可用。
- 部分单元/冒烟/桌面用例仍基于模拟试验或已撤掉的首页区块；尚未完成整体验证。

后续先修正这些中间态，不继续叠加首页功能面板。

## 四、分阶段实施

### 阶段 1：整理契约与消除中间态回归

1. 固定首页结构，以本轮恢复后的原有控件与八项参数为基线。
2. 保留纯真实入口；彻底清理遗留模拟 RPC、模拟文案与生产依赖，假串口仅留测试。
3. 将读取状态、切换记录库等非运动操作，与电机启停、回零等运动操作分开处理，不使用一个全局拒绝条件。
4. 建立八项指标的来源表，注明设备、通道、单位、标定、机械角色与派生公式；没有依据的项保持 0+不可用。
5. 修正未经确认的拉力→法向力、位移→水平速度映射；有效真实零与占位零通过质量字段区分。
6. 设备开关状态只根据真实反馈更新；通信丢失不能伪装“确认关闭”。

验收：无设备运行所有八项参数长期为 0；无模拟云图、无自动新增试验样本；普通查询/历史记录操作仍可使用；未实现动作返回明确不可用。

### 阶段 2：配置默认值、持久化与迁移

1. 逐项整理默认值的依据：协议默认、主机策略、部署端口、现场标定分别标注。
2. 统一 Python 默认值、JSON 示例和设置页生效值，避免前后端各维护一份默认参数。
3. 首次启动写出完整结构的默认文件；已有 v1/v2 配置按版本迁移，保留非空用户值和历史数据。
4. 连接参数与运动参数分开校验：端口/波特率/站号满足即可连接只读，速度/方向等仅在用户启动时校验。
5. 使用现有原子保存流程，增加默认文件创建、旧配置补值、损坏文件保护和手改文件重启生效的测试。
6. 复用设备连接页的端口扫描、选择、保存与错误展示，不给首页增加入口。

默认值边界：

| 参数 | 处理方式 |
| --- | --- |
| 升降 RS232 | 已知 38400/8N1，可以默认填入 |
| 拉力/位移通信 | 使用已确认的 9600/8N1；站号、型号需与实际设备一致 |
| 两台电机站号 | 默认分配 1/2，明确实际驱动需核对；两台同一串口 |
| 电机波特率 | 不能把其他设备的 9600 当厂家默认；按实际驱动配置填写部署默认 |
| USB 电子皮肤 | REV 0/1 可作为默认分配；不能据此假定已有 USB 驱动 |
| 物理端口 | 依据目标电脑端口分配表填入，不凭空猜 COM 号或 macOS 设备路径 |
| 运动方向/速度/加减速 | 明确为现场确认的调试参数；协议允许值不等于机械安全值 |
| 位移量程/力标定 | 无实物依据时不编造工程量；保留原始反馈，不写入首页工程量指标 |

“所有连接字段都有可用默认值”的交付条件包括取得部署端口、实际电机通信参数和实际传感器型号。未取得前应标记配置待落实，不用随意填数冒充完成；这不阻止其他已知设备自动连接。

验收：配置页和文件一致；首启生成文件；配置迁移不覆盖用户有效值；逐设备配置错误不成为整机启动门槛。

### 阶段 3：后台自动连接与单端口所有权

1. 统一启动连接与设置页重连使用的会话创建函数，避免复制线程启动/记录初始化逻辑。
2. 启动立即按生效配置逐设备发起异步连接，串口打开和响应等待不阻塞 UI。
3. 同一物理端口只能由一个会话拥有；处理 COM 大小写、串口路径别名及重复连接。
4. 允许不同独立端口的电机、升降反馈和传感器并存，不再用“任一设备活动就拒绝所有其他设备”的全局互斥。
5. 验证/诊断复用已有会话或要求明确断开对应端口，不能重复打开正在采集的端口。
6. 连接失败独立记录；打开端口后的初始化失败须释放端口、结束记录和会话，不留下半启动线程。
7. 重连放在设备连接页；先结束旧会话再建立新会话，不自动恢复运动。

验收：已配置设备启动后自动产生真实读取请求；无任何启动/使能/回零写报文；一台设备失败不阻止其他设备接收；重复连接不重复占口。

### 阶段 4：真实读数、阵列与就绪汇总

1. 在真实采集事件处写入规范化读数，保留接收时间、来源、单位和质量；不要轮询旧快照时重复刷新读数有效期。
2. 已确认来源/标定/机械角色的指标逐项接入；电机 rpm 不直接写成 mm/s；气压设定不充当实测气压。
3. 派生指标使用新鲜且对应的真实输入。速度使用可靠的时间间隔与正确轴；置零/换会话/断线后重置派生历史。
4. 缺失、无效、断线或过期时清零；后台断线及前端离线时不继续显示旧值为实时值。
5. 阵列驱动按真实 USB API 或实际串口协议接入；没有驱动时维持零网格和未就绪，不制造硬件帧。
6. 定义必需设备清单并依据真实反馈聚合状态。未实现且必需的设备仍算未就绪，不能静默忽略。

验收：八项显示与真实事件逐项对应；过期清零；缺输入时系数/面积/速度不可用；Python 在线但硬件缺失时右上显示“设备未就绪”。

### 阶段 5：原有首页控件接真实控制

1. 原有两个电机开关接已有受限 JOG/停止驱动，不另建控制区，不让用户选择模式。
2. 不要求先到设置页连接；配置正确且后台已取得有效待机反馈后，按既定运行权限允许启动。
3. 研发权限仍保护配置修改/诊断；运行授权与研发授权分开梳理，不把研发用户名/密码表单嵌入首页。
4. 停止优先于启动准备；停止不因权限过期、busy 或一般配置错误被拒绝；保持停止取消屏障和软件运行时限。
5. 升降“开启/关闭”必须先确认是哪个具体动作，再按实物协议实现；未确认前禁用原有开关，不擅自解释为上升/下降/使能。
6. 初始化、回零、置零、气压设定逐项有真实实现才启用；现有急停不冒充硬接线安全急停。

验收：首页布局与八项参数不变，没有连接/模式/研发登录新增区块；真实电机能手动启动、停止，未接入动作不能显示虚假成功。

### 阶段 6：真实记录与全链路回归

1. 试验开始前检查必要真实数据与执行条件；条件不足不创建运行记录。
2. 占位零不写为正常样本，有效真实零可以写入；运行中必要读数失效则结束记录并说明原因，不用零补样。
3. 记录结束、通信停止请求、驱动停止反馈和机械安全确认分别表述。
4. 保留历史数据库和现有用户数据目录；历史来源无法核实时不标成真实试验。
5. 更新旧模拟测试，补充首启、配置迁移、设备并存、失败清理、自动连接只读、过期清零、停止抢占等测试。
6. 执行 TypeScript 检查、Python 测试、单元测试、构建及 Electron→Python→假串口测试；截图核对首页结构未变化。
7. 最后进行现场低速单设备、全设备、限位、急停、断线测试；软件测试不替代实物验收。

## 五、执行顺序与交付边界

首页回退与计划修订（本轮） → 契约修正 → 默认配置与迁移 → 自动连接/端口归属 → 真实数据/就绪状态 → 原首页控制接线 → 真实记录/回归 → 现场验收。

不引入额外模拟模式、不增加首页连接面板、不扩展为完整电机定位/轨迹平台。

完成前五个实施阶段后，已确认协议及配置的设备可启动自动连接、显示真实读数，并通过原有开关控制两台电机。是否支持升降运动、气压设定、回零和完整试验记录，分别取决于对应驱动、机械语义、标定及验收，不能随电机启停一起笼统宣布完成。

### 7.3 首页八项来源表

| 首页指标 | 可接受真实依据 | 当前处理/尚缺依据 |
| --- | --- | --- |
| 载物台法向力 | 已确认法向力通道及 N 标定，或已标定阵列力计算 | 不能仅凭拉力单位为 N 就映射；未确认时 0+不可用 |
| 按压接触面积 | 按压阵列有效帧、接触阈值及单元实际面积 | 驱动/标定未就绪时 0+不可用 |
| 水平摩擦力 | 已确认水平力通道、方向与标定 | 不把任意拉力通道默认当摩擦力；未确认时 0+不可用 |
| 水平拖动速度 | 已确认水平位移轴、单位、可靠采样时间差，或已确认传动换算 | 位移模块型号和机械角色需确认；rpm 不当 mm/s，当前 0+不可用 |
| 动摩擦系数 | 同一试验语义下的新鲜法向力与摩擦力，分母大于 0 | 由真实输入计算；缺任一输入时 0+不可用 |
| 夹爪实时气压 | 已确认的实际气压反馈通道及 MPa 单位 | 设定值不当实测值；无通道时 0+不可用 |
| 抓取接触面积 | 抓取阵列真实帧、阈值及单元面积 | 不由按压面积乘比例；未就绪时 0+不可用 |
| 抓取力 | 已标定抓取力通道，或已确认的抓取阵列力换算 | 不由法向力乘比例；未就绪时 0+不可用 |

`RealReadings` 只是接收已规范化测量的内部接口，不提供外部写读数 RPC。单位校验不替代机械角色和标定确认，当前独立采集的原始反馈不自动填入以上工程量。
