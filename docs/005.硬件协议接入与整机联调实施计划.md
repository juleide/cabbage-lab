# 硬件协议接入与整机联调实施计划

编写日期：2026-11-01  
状态：待实施；本文不代表已完成驱动开发或实机验收。

## 一、实施目标

保留现有 Electron + React + Python 架构、界面风格和模拟试验功能，逐步实现：

1. 在设备连接设置页扫描端口、选择设备、保存连接参数。
2. Python 统一管理真实设备连接、通信、采集和异常。
3. 接入电机、升降、拉力、位移及电子皮肤设备。
4. 界面准确展示通信状态、执行状态和数据有效性。
5. 完成单设备验证、整机联调及目标平台交付。

实施原则：先配置闭环，再只读采集，最后运动控制；协议明确的先做，资料缺口按设备隔离，不阻塞其他部分。

## 四、总体技术方案

### 4.1 分层设计

按职责增量整理，不一次性重写控制程序：

```text
React 设置页 / 试验界面
          |
Electron IPC 白名单
          |
Python RPC 与控制器
          |
连接管理 / 设备状态 / 操作联锁
          |
设备驱动
  电机 / 升降 / 拉力 / 位移 / 电子皮肤
          |
通信层
  串口枚举 / 资源管理 / Modbus RTU / 自定义数据流 / USB SDK
```

模拟与真实实现使用一致的上层数据契约，但不强行让所有设备共用一个过于简单的 `read()/set_output()` 接口。

### 4.2 通信执行模型

采用控制状态单一归属、后台 I/O 工作线程及消息队列：

- 控制器负责业务状态、联锁和记录写入。
- 工作线程负责阻塞 I/O，不直接修改控制器状态或操作 SQLite。
- 每个串口由一个通信实例独占，同一 Modbus 总线只有一个未完成事务。
- 采集结果、命令结果和故障通过队列返回控制器。
- 采样任务有界合并，避免请求积压。
- 停止请求优先于尚未发送的普通任务，但不能中断已经在物理链路上的报文。

停止响应上限必须通过设计和实机测量确认，不能因采用线程就宣称具有实时安全保证。

### 4.3 状态分离

| 状态类别 | 建议表达 |
| --- | --- |
| 配置 | 未保存、已保存未应用、已应用 |
| 连接 | 未配置、未连接、连接中、已打开待验证、通信正常、故障 |
| 执行 | 未知、待机、执行中、已完成、故障、结果未确认 |

端口已打开、通信验证通过和设备允许运动必须分别判断。请求状态与设备确认状态分开存储。

## 五、分阶段实施

### 阶段 0：统一资料与接入契约

工作内容：

1. 修正文档中电机数量及电子皮肤端口分配冲突，维护实施计划链接。
2. 建立设备确认表：实物型号、接口、供电、站号、通信参数、协议来源和确认结果。
3. 为每种设备登记可实现、待确认及禁止自动执行的操作。
4. 梳理现有界面字段与真实测量值、设备动作的映射。

特别确认以下数据语义：

- 单个拉力模块实际测量法向力还是摩擦力，另一种力是否具备来源。
- 接触面积是否具备像素物理尺寸、有效点判定及计算依据。
- 电机速度是脉冲速度，还是已按传动关系换算的线速度。
- 气压是否有对应传感器或调压执行器协议；升降电动控制器不能替代气压阀协议。
- 摩擦系数的分子、分母、单位及有效性条件。

没有真实来源或计算依据的字段，在真实模式显示未接入或不可用，不沿用模拟公式生成假数据。

验收：设备清单、协议能力表和测量映射表齐备，未确认事项按设备登记。

### 阶段 1：完善端口扫描和配置保存

#### 后端枚举

建议使用 PySerial 系统枚举接口，返回端口路径、系统描述、制造商及可用的 VID/PID、序列号、位置等辅助信息。

扫描仅枚举，不打开端口、不发送报文。依赖缺失返回功能不可用，不能伪装成没有找到设备。

#### 设置页

- 扫描按钮调用真实接口，展示端口及描述，支持刷新和手动输入。
- 选择端口只修改草稿，不自动连接。
- 多端口时不自动替用户选择。
- 已保存端口暂时不存在时保留配置并提示。
- 区分扫描失败和扫描结果为空。
- 保留当前视觉风格、研发解锁及未保存提醒。

#### 持久化

复用 `HardwareStore`，补充可选设备身份信息、配置版本迁移、旧配置兼容、规范化值回显及保存/应用差异提示。

VID/PID 通常不能唯一识别设备；序列号可能缺失或重复。身份信息仅辅助提示，端口变化时不据此自动重绑执行机构。

验收：扫描无动作，保存后重启恢复，拔线不丢配置，错误提示准确；两个电机只配置一个串口，不同设备类型不能占用同一端口。

### 阶段 2：通信资源与连接生命周期

实现打开、关闭、连接和写超时、端口独占、电机共享总线顺序访问，以及验证、采集和断开共用的资源管理。

每次连接生成会话标识；配置应用或重连后，旧请求的迟到结果不得更新新会话。退出时停止任务并释放线程和句柄。

配置应用策略：

- 保存不等于连接，不隐式断开或重连。
- 首期不做配置热切换。
- 停止试验、确认相关机构状态允许、断开后再应用。
- 后端执行互锁，不只依赖界面禁用。
- 应用失败不能显示已应用成功。

Modbus 底座统一处理 RTU 时序、CRC、站号、功能码、长度、异常响应和写响应匹配，以及半包、粘包、噪声、残留和迟到响应。

只读查询可有限重试；运动触发、去皮、校准等写操作不得采用通用自动重试。超时不等于未执行，应标记结果未确认，再通过适当反馈核实。

验收：不重复打开端口、不抢读、不阻塞控制主循环；断开、重连及退出不遗留资源。

### 阶段 3：只读通信验证

建议新增独立 RPC，名称可按现有项目风格调整：

| 接口示意 | 职责 |
| --- | --- |
| `hardware.ports.list` | 枚举串口 |
| `hardware.status` | 获取连接及能力状态 |
| `hardware.verify` | 安全地验证通信 |
| `hardware.connect` | 建立持续连接 |
| `hardware.disconnect` | 受控断开 |

同步修改共享类型、IPC 白名单、参数校验及权限控制，不把真实探测塞进现有配置字段检查。

| 设备 | 首期验证 |
| --- | --- |
| 电机 | 按配置站号读取状态字、位置或速度 |
| 拉力 | 读取地址 0～1 |
| 位移 | 按所选 P/G 型号和读取方式查询 |
| 升降 | RS232 等待合法高度反馈；无反馈报告未验证，不发送猜测命令 |
| USB 阵列 | SDK 完整后实现，此前明确提示能力限制 |

打开串口可能改变 DTR/RTS 或使部分设备复位，应依据实物资料确认控制线行为。验证不改变参数、不使能、不运动、不清错。

验收：区分端口不存在、打开失败、无有效响应、报文错误及有效响应。无法识别型号时只显示通信验证通过，不显示型号已确认。

### 阶段 4：拉力与位移连续采集

#### 拉力

- 一次读取完整两个寄存器，按低字在前的 int32 解析，支持负数。
- 根据配置小数位缩放，单位由标定约定决定。
- 首期不做设备去皮和校准。
- 后续写操作落实至少 500 ms 写后等待，不因收到应答而省略。

#### 位移

- 按明确选择的 P/G 型号和通道使用对应地址。
- 分别处理原始值换算和大端 float32，一次读完整数据。
- 检查有限值、换算范围和合理行程。
- 软件相对置零保留原始值和偏移，不改写未知寄存器。

#### 测量、界面与记录

统一结果至少包含原始值、工程值、单位、来源、主机接收时间、有效/过期/错误状态及原因。主机接收时间不能标为设备实际采样时间。

不同传感器不能默认同步采样；联合计算需定义允许的时间差。通信失败不记成有效的 0，最后读数过期后不继续当实时值使用。

记录保留模式、配置摘要及质量信息；确定关键传感器故障是否结束试验。日志按状态变化和限频汇总，避免每次轮询失败刷屏。

验收：覆盖负拉力、字序、小数位、位移型号差异、异常 float、越界、超时和拔线。

### 阶段 5：电机与升降控制

#### 先定义真实操作语义

逐项明确电机启动属于使能、JOG 还是定位，停止方式，回零方向及速度，升降按钮语义，初始化范围和急停解除行为。

不能将模拟开关直接替换为硬件命令。急停解除不自动续跑，设备去皮、软件偏移及阵列基线修正也不能混为统一置零操作。

#### 电机能力开放顺序

1. 状态、位置和速度读取。
2. 受控使能与释放。
3. 低风险单轴动作。
4. 停止与状态确认。
5. 参数已确认的定位或 JOG。
6. 回零。
7. 两电机联动试验。

目标参数写入与运动触发作为受控序列，避免其他普通任务插入；触发超时不自动重发。机械换算需有脉冲当量、传动比及有效行程依据。

#### 升降

先接收位置反馈，再按实际型号和接口开放已确认的命令。不自动复位、清错或调用记忆位置；高度反馈不直接当动作 ACK。缺少已停或到位判据时保留未确认状态。

#### 安全与验收

- 停止尝试与停止确认分别记录，断线不显示已停止。
- 急停锁定后禁止普通动作，取消未发送动作任务。
- 重连重新确认状态，不恢复旧动作队列。
- 崩溃、主机断电及线缆断开的安全行为依赖硬件设计并独立验收。
- 先单设备测试，再整机；未确认停止、限位和行程前不开展自动试验。

### 阶段 6：电子皮肤真实采集

本阶段可并行推进，SDK 缺失不阻塞其他设备接入。

补充 SDK 与平台支持、USB 枚举及开关接口、REV 读取选择、启停与授权、CRC、点值符号、物理标定等资料。

实现设备与会话隔离、按压/抓取绑定、重复 REV 检测、数据流与现有组帧衔接、重连残包清理、基线有效性管理及有界最新帧缓存。展示来源、帧率、丢帧及校验状态。

模拟 CRC 不得当作真实 CRC。算法未确认时，结构解析仅用于明确标为未校验的受限调试，不宣称链路通过验收。没有物理标定时保留原始值，不标注 N、Pa 等单位。

### 阶段 7：整机流程、记录及交付

建立待机、条件检查、试验运行、正常结束、故障终止、急停锁定等状态及转换规则。

启动条件至少包括真实模式明确、必需设备通信正常、关键数据新鲜有效、执行机构状态满足要求、配置已应用，以及没有未完成危险动作或急停锁定。

试验中关键设备故障后按策略结束记录、尝试停止并保留结果，不能仅弹提示继续运行。

交付工作：

- 声明 Python 依赖和开发安装方式，核实 Electron 包的 Python 分发方式。
- 纳入 PySerial、USB 库及厂商 SDK，明确系统驱动、权限和授权要求。
- 在无开发环境的目标机器验证安装启动。
- 交付驱动、设置页、自动化测试、实机记录、接线参数表、排障说明及能力清单。

## 六、测试与验收安排

| 层级 | 重点 |
| --- | --- |
| 单元测试 | CRC、帧解析、字序、换算、迁移、联锁 |
| 模拟通信测试 | 半包、粘包、错误 CRC、异常响应、迟到响应、超时 |
| 子进程集成 | RPC、事件、退出、配置恢复、记录一致性 |
| 界面测试 | 扫描、选择、草稿保护、保存/应用、离线及错误状态 |
| 实机单设备 | 参数、报文、读数、反馈、拔线和重连 |
| 整机测试 | 启停顺序、故障终止、急停和长时间稳定性 |
| 交付测试 | 非开发环境安装、依赖、驱动和目录权限 |

自动化测试不默认访问真实串口；硬件测试单独启用，运动测试需人工确认和现场安全条件。具体响应时限及稳定性指标在设备确认后形成可测量验收值，不随意填入未经验证的数值。
