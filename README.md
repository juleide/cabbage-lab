# 甘蓝检测多功能试验台

基于 Electron、React、TypeScript 和 Python 的桌面试验控制应用。界面面向 1024 × 600 横向触屏设计，并随窗口等比例缩放。

当前按 `docs/014.保持首页结构的真实硬件接入实施计划.md` 改造为纯真实硬件接入。保留原首页布局与八项参数，生产模拟源已移除；没有明确真实来源的指标显示 0。启动自动连接与设置页共用连接管理，原首页两个电机开关已接受限真实启停；真实整机测量、联动试验及现场验收尚未完成。

设备连接页现仅保留通信/解析参数、串口扫描、保存与简洁连接状态/重连。电机运行参数仍保存在 `config/hardware.json`，不再提供编辑大面板；详细诊断、独立采集记录和运动安全规划界面已撤下，后台采集及停止保护保留。下文相关历史能力说明不代表这些调试面板仍在页面展示。

## 功能概览

- **设备控制**：首页原有控件保留，未接入动作明确拒绝，不返回虚假成功；真实电机独立启停当前在设备连接页使用。
- **联动试验**：真实联动尚未接入，不能创建占位试验；支持软件急停锁定和确认解除。
- **实时参数**：法向力、按压接触面积、摩擦力、速度、动摩擦系数、气压、抓取接触面积和抓取力。
- **压力云图**：保留解析器、修正算法与绘制组件；真实采集卡驱动待接入，当前不生成压力帧。
- **数据管理**：SQLite 保存试验及采样数据，提供当前／归档两个逻辑记录库，支持最近记录查看、CSV 导出和运行日志查看。
- **应用设置**：白色／黑色／科技蓝主题、默认气压、采样间隔、记录前缀、默认记录库、数据目录及控制端诊断。主题自动保存，下次启动恢复。

> 无模拟/真实模式切换。原始反馈不等于已经确认首页机械量映射；单位相同也不自动将拉力当法向力或将位移当水平速度。软件停止指令、串口回显或关闭端口均不能证明机械已停止，不能替代硬接线急停、安全联锁及设备侧保护。

## 技术架构

```text
React 界面
    │ 受限 preload API
Electron 主进程
    │ stdin / stdout JSONL
Python 控制进程
    ├── 设备状态与试验流程
    ├── 真实设备会话与读数质量
    ├── JSON 配置
    └── SQLite 试验记录与日志
```

- **界面层**：React 19、TypeScript、CSS，负责展示、交互及云图绘制。
- **桌面层**：Electron 40，负责窗口、Python 子进程管理、受限 IPC、原生导出对话框和目录打开。
- **控制层**：Python 负责真实设备会话、命令校验、读数质量、配置和记录存储；串口访问使用 PySerial。
- **构建工具**：electron-vite、Vite、electron-builder、pnpm。

设备状态以 Python 控制进程为唯一来源，React 不再自行生成设备状态或试验采样。控制端断开时，界面提示状态未知并限制设备操作。

### 一次性只读通信验证

在“设备连接”中进入电机、拉力或位移分类，保存配置并完成配置检查后，可点击“连接验证”。操作前需停止试验及全部执行机构，并确认现场安全。

- 电机按两个已配置站号依次读取 `0x0004` 状态字，共用一次串口连接。
- 拉力读取地址 0～1，按低字在前的 int32 和配置的小数位解析；单位依赖实物标定。
- 位移按所选 P/G 型号、通道及读取模式查询，使用配置量程换算或解析 float32。
- 验证在后台执行，可取消；结束后关闭端口，不建立持续连接，不授予运动许可，也不创建联动试验。
- 一次只允许一个验证任务；验证期间禁止修改设备配置及普通设备操作，停止和急停仍可调用。
- 不自动重试，不扫描站号，不发送运动、使能、清错、去皮或校准指令。当前验证仅支持站号 1～247。
- 打开端口前设置 DTR/RTS 为低，但适配器或系统仍可能产生控制线变化；打开端口并非对所有硬件都绝对无副作用。
- 验证通过仅证明本次响应符合预期，不证明型号、标定、机械安全或允许运动；结果不是实时测量值。
- 升降和电子皮肤暂不支持此项验证；真实运动和 USB SDK 接入尚待后续阶段。

开发回归测试：`python3 scripts/hardware-verification-test.py`。测试使用模拟串口及隔离子进程，不访问真实设备。

### 拉力与位移持续采集

在设备连接页保存实际通信参数后，进入连接概览或拉力与位移分类，使用“连接拉力并采集”或“连接位移并采集”。连接前仍需确认设备型号、单位、标定和现场安全；程序不会自动写设备参数。

- 每种传感器独占配置串口，两种设备可同时只读采集；同一端口或可识别的别名不能重复占用。
- 使用已保存配置的固定快照，并显示会话和配置指纹；采集中可以保存新配置并触发该设备关闭后只读重连，原会话快照不变；禁止重复占用端口的一次性验证。
- 采集间隔使用 `intervalMs`，超时使用 `timeoutMs`；主机轮询频率不等于设备采样频率，落后的轮询不补发积压任务。
- 过期阈值为 `max(1000, 3 × intervalMs)` 毫秒，按单调时钟计算；等待慢响应期间也会隐藏过期的当前值。接收时间仅代表主机接收时间，不是设备采样时间。
- 任一通信、解析或记录缓冲错误结束对应会话并关闭串口，不自动重试或重连，不用 0 或模拟数据填充失败读数。另一个独立传感器不因此自动停止。
- 位移相对置零仅设置本会话的软件偏移，不向设备写寄存器；原始值、绝对换算值、偏移和置零事件保留，重新连接后偏移归零。
- 连接即开始独立记录，断开即结束；停止、急停、系统休眠和控制进程退出也会请求断开全部传感器。
- 离开设置页或研发权限锁定不停止只读采集；可返回试验台使用停止/急停，或重新解锁后断开。后台状态轮询不延长研发权限有效期。
- 工作线程只负责串口和有界缓冲，主控制线程写 SQLite；缓冲溢出明确终止，不静默丢弃数据。异常退出的未结束会话下次启动标记为异常中断。

数据仍位于数据目录的 `data/experiments.sqlite3`，使用独立的 `sensor_runs`、`sensor_samples` 表，记录来源固定为 `hardware`，不作为联动试验的 `runs`、`samples` 或原 CSV 导出。设置页可刷新最近 20 次真实采集会话，并按每页 50 条查看采样、数据过期、软件置零及结束事件。

当前提供的是独立传感器采集，不是整机真实试验模式；没有把拉力默认映射为摩擦力/法向力，也没有用位移推算速度或伪造真实云图。整机测量映射、同步计算、真实试验流程和专用导出仍需后续实现。

回归测试：`python3 scripts/hardware-sensors-test.py`。实际使用前需安装 `backend/requirements.txt`，现阶段自动化测试不访问真实硬件。

### 执行机构状态与停止诊断（D2，禁止真实启动）

`backend/src/lab_controller/devices/motion_protocol.py` 提供受限编解码；`devices/motion.py` 提供后台串口会话。在「设备连接 → 执行机构」保存配置后，通过独立诊断面板连接：

- 电机固定两个站号，共用串口，依次读取状态字和原始位置；只支持协议波特率及站号 1～247。连接时不发送启动、使能或清错。
- 升降仅开放 RS232 38400/8N1，监听高度/错误反馈，不发送猜测查询；RS485 暂不开放。没有反馈不代表在线，也不能推断已停。
- 面板可向两个电机发送停止/软件急停，或发送升降普通停止。停止队列按目标合并，软件急停优先于未发送普通停止；可中断只读等待，新急停可中断停止 ACK 等待。停止写不自动重试，超时/短写为结果未知。
- 电机 06 回显仅表示收到匹配报文，可能受适配器本地回显影响，不代表机械已停。升降无明确 ACK，仅显示已发送/结果未确认。
- 断开会尽力发送停止后关闭端口；离开调试页、权限锁定/超时、休眠及退出会请求停止并断开。普通停止/主界面急停也覆盖已连接诊断会话；没有连接的设备不会自动打开端口发送指令。
- 故障位/错误反馈以及电机运行/软限位会触发诊断联锁，锁存原因、请求停止并关闭该会话；通信读取失败则终止会话并标记故障，不声称停止送达或断线制动。任何失败都不自动重连、清错或续跑；未知停止结果必须现场检查。
- 诊断、持续传感器采集与一次性验证可在独立端口并行；同一物理端口不能重复占用。执行机构静止时可保存配置，仅变化的活动设备关闭后只读重连，不恢复运动；运动中禁止保存配置。重启前须先停止并断开诊断。
- 配置快照、会话、命令编号及停止结果写入原 SQLite 运行日志，不写入联动试验采样/CSV。反馈新鲜度采用主机单调时钟和本地阈值，不等于厂家反馈周期确认。

本诊断会话仍禁止启动、使能、释放、回零、上升、下降、目标定位和任意寄存器写入；独立电机控制会话见后文。系统驱动阻塞、适配器故障或进程被强杀时，软件无法保证停止送达，必须配置独立硬接线急停。实际设备尚未验收。

回归测试：`python3 scripts/motion-protocol-test.py`、`python3 scripts/hardware-motion-test.py`、`pnpm exec playwright test tests/desktop/motion.spec.ts`。后续运动参数及机械安全确认项见实施计划 D2 记录。

### 运动安全草稿与离线规划（D3，不授权执行）

「设备连接 → 运动安全」可保存两个电机及升降的行程、单次距离、标定、速度/时长约束和核验材料引用到数据目录的 `config/motion-safety.json`。未知值默认留空，可手动修改文件并重启应用；损坏或外部修改不会被静默覆盖。D3 最初未改变连接配置；按 docs/012 实施后 `hardware.json` 已升级为 v2，见下方说明。

- 显式绑定当前已加载的电机/升降连接配置指纹；连接参数变化会使绑定失效。配置绑定不是设备身份核验。
- 页面展示缺项和阻断原因；资料引用不是安全验收，完整草稿也不能开启真实运动，`canExecute` 始终为 `false`。
- 目标草稿完整、已保存且绑定匹配时，可根据人工起点计算目标脉冲/高低字或升降位置 ASCII 数值；不读取实际位置、不生成报文、不打开串口，不预测到位时间。
- 新增时长/反馈/停止等待字段目前是规划草稿，不替代 D2 诊断策略，也不代表已实现运行看门狗。
- 保存有版本冲突检查及活动设备互锁；未保存草稿、配置变更和外部文件修改会限制新计算，已有停止入口不依赖草稿完整性。

空白示例：`docs/examples/motion-safety.example.json`。字段说明、手动修改流程及现场核验清单见 `docs/008.运动安全配置与现场核验清单.md`。测试：`python3 scripts/motion-safety-test.py`。

### 电机原始位置反馈（D4a，只读）

执行机构诊断按 `motor1 状态 → motor1 位置 → motor2 状态 → motor2 位置` 串行读取同一总线。位置一次读取 `0x0008/0x0009` 两个寄存器，保留高低字及无符号原始位值；不推测符号、不转换机械毫米。状态与位置分别记录接收时间和新鲜度，不是同时快照，也不构成安全停机证明。

位置等待可被停止请求打断；位置应答超时/校验失败沿用诊断故障结束策略，不自动重试、不自动重连。活动会话结束时位置立即不可作为当前值。能力评估区分“位置缺失/过期”和“位置解释未经核验”；即使读到有效原始位置，真实执行仍禁止。

协议依据、接口字段、故障边界和现场验收步骤见 `docs/009.电机原始位置反馈与验收说明.md`。本批次不是完整 D4 运动许可或真实启动实现。

### 后台诊断联锁（D4b 基础，不授权运动）

执行机构后台增加独立观察线程，约每 50 ms 检查已收到反馈的新鲜度，不依赖界面轮询。已有状态/位置过期，或收到故障、电机运行/软限位时，锁存首次原因、请求该会话全部目标停止并关闭端口。电机使用软件急停，升降仅发送已知普通停止，不自动清错或重连。

面板展示等待反馈、后台观察、触发锁存、结束四种诊断状态；观察不代表在线或安全，关闭/停止回显也不代表机械已停。没有首份升降反馈时仍可保持等待，不猜测厂家首帧超时；升降曾收到反馈后过期关闭可能是保守策略误报。50 ms 不是实时停止保证，系统阻塞/通信异常可能使停止无法发送。

详细行为、会话级隔离及未完成的整机安全门槛见 `docs/010.诊断联锁状态机与验收边界.md`。诊断本身不提供跨设备联锁、可信物理位置、短时运动许可或启动能力；独立电机控制进度见后文。

### 电机最小启停实施进度：独立控制与配置 v2

设备连接页保留一个电机串口和两个站号，新增每台电机的方向、运行速度、安全速度上限、加减速时间和单次运行时限草稿。未知值留空；保存/扫描/只读验证不启动设备。电机通信限制为 1～247 不重复站号、9600/19200/38400/115200 和 8N1/8N2/8E1/8O1。

`config/hardware.json` 当前 schemaVersion 为 2，新增 `motors.operation.motor1/motor2`，原站号字段不变。旧 v1 文件仅在内存迁移，显式保存后才写 v2；旧的不支持通信值保留并提示修正，不自动改号或改波特率。手动修改前备份，停止并断开后编辑，重启载入；不要同时用编辑器和程序写入。

运行参数支持 null 草稿。速度与上限为整数 1～3000 r/min 且速度不大于上限；方向 ±1；加减速各 1～2000 ms；maxRunMs 为 1～3600000 ms（本地软件界限，不是硬件保证）。示例：`docs/examples/hardware.v2.example.json`。扩展 motors 结构会使旧运动安全草稿指纹失配，需显式重新绑定；不会自动修改安全草稿。

**设备连接页已接入独立真实电机固定参数启停，但尚未实物验收。** 连接仅监测反馈，启动才写入 JOG 参数并触发一次；不自动使能、清错或续跑。生产模式切换已移除，首页恢复原结构且控制接线待后续阶段完成。后台监督状态、速度与单次时限，超时停止不是硬件保护；停止应答不等于机械安全。当前进度与后续顺序见 `docs/014.保持首页结构的真实硬件接入实施计划.md`。

### 安装与启动

```sh
cd lab-control-app
pnpm install --frozen-lockfile
pnpm dev
```

开发模式启动 Electron、前端开发服务器及 Python 控制进程。前端修改支持热更新；修改 Python 代码后，在设置页的「运行与诊断」中重启控制进程。修改启动逻辑或环境变量后，重新运行 `pnpm dev`。

首次启动保持待机，不会自动启动执行机构或联动试验。

项目的 `.npmrc` 默认使用 npm 镜像。如需使用官方源安装：

```sh
pnpm install --frozen-lockfile --registry=https://registry.npmjs.org
```

Electron 安装过程需要下载对应平台的运行文件，请勿跳过所需安装脚本。`pnpm-workspace.yaml` 已允许 Electron 和 esbuild 的构建脚本。

| `LAB_PYTHON` | 指定开发运行时使用的 Python 解释器，默认 Windows 为 `python`，macOS／Linux 为 `python3` |
| `LAB_DATA_DIR` | 指定独立的控制配置、试验数据和日志根目录，适合本地调试 |
| `LAB_EXPORT_MAX_ROWS` | 每个 CSV 的最大采样记录数，不含表头；项目 `.env` 初始配置为 **5000**。必须是正的安全整数 |

macOS／Linux：

```sh
LAB_PYTHON=/path/to/python3 LAB_DATA_DIR=/path/to/lab-data pnpm dev
```

Windows PowerShell：

```powershell
$env:LAB_PYTHON = "C:\Python312\python.exe"
$env:LAB_DATA_DIR = "D:\LabControlData"
pnpm dev
```

这些变量应在启动 Electron 前设置；`LAB_DATA_DIR` 不改变主题偏好的保存位置。

项目根目录 `.env` 已包含：

```dotenv
LAB_EXPORT_MAX_ROWS=5000
```

直接修改该文件即可调整阈值，**下一次导出生效，无需重新构建**；同一导出任务始终使用开始时读取的阈值。文件仅用于非敏感的导出参数，不要放入密钥或账号密码。

优先级为：系统环境变量 → 配置文件 → 内置默认值 5000。打包时 `.env` 会复制到应用资源目录的 `config/export.env`，安装后的导出读取该文件。

如需用系统环境变量临时覆盖为 500,000 条：

```sh
# macOS / Linux
LAB_EXPORT_MAX_ROWS=500000 pnpm dev
```

```powershell
# Windows PowerShell
$env:LAB_EXPORT_MAX_ROWS = "500000"
pnpm dev
```

初次调试直接 `pnpm dev` 即使用 `.env` 中的 5000。系统环境变量由启动进程继承，修改它后需重新启动应用；修改配置文件则下一次导出即生效。此处只从配置文件读取 `LAB_EXPORT_MAX_ROWS`，不将其他键加载到进程环境。空值、零、负数、小数或非数字会在导出时提示配置错误，不静默忽略。

## 开发约定

- UI 采用 React 声明式事件和状态渲染；组件内不通过 `innerHTML` 拼接界面。
- 设备状态与操作约束放在 Python 控制层，界面禁用状态不能代替后端校验。
- 新增设备命令时，同步调整共享类型、IPC 白名单、Python 请求处理及界面调用。
- Node.js／文件系统能力保留在主进程，通过 preload 暴露明确用途的接口。
- stdout 仅传输控制协议消息，Python 运行日志写入文件，异常输出由主进程收集。
- 设备动作超时后不自动重试；先确认设备状态，避免重复执行。
- 退出、休眠和控制端通信中断时执行停止流程；重启控制端后不自动恢复试验。

## 数据与配置

为兼容已有配置和历史数据库，默认数据根目录仍保留 Electron `userData` 下的历史名称 `simulation/`。这只是目录名，不代表仍有模拟运行模式；也可用 `LAB_DATA_DIR` 指定：

```text
simulation/
├── config/controller.json       # 试验配置
├── data/experiments.sqlite3     # 试验、采样数据及操作日志
└── logs/
    ├── controller.log           # Python 运行日志，按大小轮转
    └── desktop-controller.log   # 控制进程异常输出
```

主题偏好独立保存于 Electron `userData/ui.json`，界面同时缓存所选配色。具体数据、配置和日志路径可在「设置 → 数据与日志」中查看并打开。

当前默认试验配置：

| 配置 | 默认值 | 约束 |
| --- | --- | --- |
| 默认夹爪气压 | 0.35 MPa | 设定草稿，范围 0～0.6 MPa；不是实测反馈或安全限值 |
| 采样间隔 | 100 ms | 100～5000 ms 的整数，同时影响参数刷新与记录频率 |
| 试验记录前缀 | `EXP` | 1～24 位英文字母、数字、短横线或下划线 |
| 默认记录库 | 当前记录库 | 当前／归档两个逻辑分类 |

修改试验配置前须停止试验和全部执行机构。配置保存后立即生效，默认气压只是配置值，当前初始化和实际气压写入尚未接入，不据此改变真实硬件。

试验数据不会因页面刷新、初始化或程序重启而删除。设置页显示所选记录库最近 50 次试验，可按记录导出 CSV。归档记录库是独立逻辑分类，不会自动搬移或归档记录。

CSV 采用 UTF-8 BOM 编码，包含时间、六项基础参数以及派生的抓取接触面积、抓取力。导出时先固定记录数量，再分页读取，避免导出过程中新增采样改变结果。

### 大记录分文件导出

导出的仍是单次试验，而不是整个数据库。首页与历史记录页共用以下规则：

- 快照记录数不超过 `LAB_EXPORT_MAX_ROWS` 时，沿用单个 CSV 的保存对话框。
- 超过阈值时，先提示记录总数及 CSV 数量，再选择保存目录。程序在所选位置创建带试验编号、时间与随机后缀的独立文件夹。
- 分卷名为 `<试验编号>-part001.csv`、`part002.csv` 等，每个 CSV 有独立的 BOM 和完整表头；末卷只保存剩余记录，不产生空分卷。
- 仍以最多 250 条分页读取，并在文件边界缩小分页，避免重复或遗漏。新增采样不进入已经固定的导出快照。
- 全部分卷在临时目录完成并关闭后，才发布为正式导出目录。正常导出异常会清理本次临时数据，SQLite 记录不受影响。程序被强制结束时可能遗留临时目录。

默认 5000 条阈值下，5000 条导出为一个 CSV，5001 条为两个 CSV（5000 + 1），10000 条为两个 CSV，10001 条为三个 CSV。无进度条或运行中取消功能；分卷不能消除磁盘不足、权限或数据库查询超时等问题。

实现说明见 [大记录分文件导出](docs/004.大记录分文件导出实施说明.md)。


## 阵列采集与云图链路

详细计划与实施结果见 [阵列采集与云图改造实施计划](docs/阵列采集与云图改造实施计划.md)。

```text
真实采集卡驱动（尚未接入，当前不产生帧）
  → 64 行二进制包（每行 136 字节）
  → 增量拆包 / CRC / 点位重排 / 64 行拼帧
  → 最新完整帧缓存
  → 最多 10Hz pressure.frame 事件
  → Canvas 读取最新 4096 点阵列
```

- 云图已不再由前端公式生成。按压／抓取模式由 Python 确认后切换，阵列零点修正独立于标量置零，急停暂停阵列并清空画面。
- 解析器支持半包、粘包、噪声、帧内行乱序与帧号 `255 → 0`。重复行不重复计数，残帧在 500ms 超时或新帧到来时丢弃，数据源变更时重置解析缓存。
- 事件发布和 Canvas 绘制上限各为 10Hz，当前没有真实帧输入。测试数据发生器仅位于 `scripts/fixtures/`，不打包为生产采集源。
- Canvas 默认按 0～4095 线性映射颜色，可在设置页调整上下限；色标显示原始／修正值，不表示电压或实际压力。超过 1 秒无新帧或控制端离线时，淡化最后画面并显示非实时提示。
- 只在内存保留最新阵列，不向 SQLite 或 CSV 添加阵列数据；现有标量记录和导出格式不变。

**协议边界**：离线测试夹具使用 CCITT-FALSE；该算法只存在于测试目录，不代表采集卡实际 CRC，生产解析器必须注入已确认的校验函数。当前未开放真实 USB 输入；需要厂家确认驱动／接口、CRC、有符号编码、标定参数和两种模式的数据来源后，才能接入真实采集。原始 16 位数据不擅自转换为压力，也不用于计算真实面积或力。

### 云图修正与查看

- 点按首页云图查看 1～64 行列坐标、原始值和修正值；标题旁的展开图标打开云图详情，显示放大阵列及原始／显示统计。
- 在设备无负载、试验停止、全部执行机构关闭且未急停时，可从详情页执行“阵列零点修正”：收集 25 个完整原始帧逐点求平均，默认 3 秒超时。“取消修正”恢复原始值显示。
- 修正不修改原始阵列。重新修正失败时保留旧基线；模式切换、初始化、急停或重启清除基线，普通停止试验保留。基线不保存到磁盘。
- 首页“传感器置零”尚未接入；独立位移采集支持设备连接页的软件相对置零，不能冒充硬件去皮或阵列修正。
- 在“设置 → 云图显示”拖动色带的上下限手柄，直观调整低值颜色与最高颜色对应的数值；支持触摸和方向键微调。滑条两端固定为 −4095 和 4095，拖动、保存及重新打开页面均不改变刻度。展开“精确设置”可在该范围内输入负数和小数。调整只影响草稿，点击“保存并应用”后才应用到首页并记住；“恢复默认”直接保存为 0～4095。范围外仅钳制颜色，不截断读数或统计，保存显示范围不会覆盖主题。
- “设置 → 运行与诊断”展示采集帧率、界面接收帧率、最近完整帧、有效帧及错误计数、修正状态。未标定的阵列数值不表示实际压力或力。

完整方案见 [实施计划](docs/云图处理与交互增强实施计划.md)，实现约定见 [云图处理与交互增强实施说明](docs/云图处理与交互增强实施说明.md)。本轮没有增加阵列历史存储，现有标量 SQLite 记录和 CSV 格式保持不变。

### 构建环境准备

最终用户安装 **Windows x64 NSIS `.exe` 安装程序**后，无需安装 Python、pyserial 或配置 `LAB_PYTHON`。主程序自动启动内置控制端，不弹出额外控制台窗口；首页、设备连接及自动连接行为不变。USB 转串口驱动、接线、端口和设备地址仍需与现场硬件匹配，不新增驱动安装或未实现的硬件功能。

构建者需要 Node.js 22.12+、pnpm 和 **Python 3.10+**。推荐使用 Python 3.12 的项目虚拟环境；Windows x64 必须使用 Windows x64、x64 Node.js 和 x64 Python 原生构建。Mac 只能构建和验证本机架构版本，不能生成 Windows 内置控制端。

Windows x64 请按下方“Windows x64 完整打包步骤”操作。

```sh
# macOS / Linux：仅构建本机平台和架构
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-build.txt
pnpm install --frozen-lockfile
pnpm package
```

运行依赖位于 `backend/requirements.txt`，构建依赖位于 `backend/requirements-build.txt`（固定 PyInstaller 6.16.0）。构建脚本按 `LAB_PYTHON` → 项目 `.venv` → `backend/.venv` → 系统 Python 的优先级选择解释器。显式指定 `LAB_PYTHON` 时必须指向有效的 Python 3.10+ 可执行文件；选中解释器缺少依赖或架构不符会停止并提示，不自动安装或修改全局环境。

首次构建还需按现有配置流程从 `.env.example` 复制生成本地 `.env`（已有文件不要覆盖），未设置调试凭据则保持为空。不要放入开发机硬件配置。

### Windows x64 完整打包步骤

以下命令均在 **Windows x64 的 PowerShell** 中执行。必须使用 x64 Node.js 和 x64 Python 原生构建；不能用 Mac 生成的控制端替代 Windows 控制端。

| 工具 | 要求 |
| --- | --- |
| Node.js | x64，22.12+，推荐 24 LTS |

| Python | x64，推荐 3.12；安装时包含 Python Launcher，以使用 `py` 命令 |
| Git | 使用 Git 获取项目时需要 |

如尚未安装指定版本的 pnpm：

```powershell
npm install -g pnpm@11.13.0
```

确认平台、架构及版本：

```powershell
node -p "process.platform + '/' + process.arch"
# 应为 win32/x64

pnpm --version
# 应为 11.13.0

py -3.12 -c "import sys, struct; print(sys.version); print(struct.calcsize('P') * 8)"
# Python 应为 3.12，最后一行应为 64
```

#### 2. 获取项目代码

将包含本次内置控制端改动的完整项目放到 Windows，进入项目根目录，例如：

```powershell
cd C:\Projects\cabbage-lab
```

通过 Git 获取时，确保新增文件和修改均已同步。不要直接复制 Mac 的 `node_modules/`、`.venv/`、`out/` 或 `dist/`；Windows 会重新安装依赖并构建自己的控制端。

```powershell
pnpm install --frozen-lockfile

```

无需激活虚拟环境，构建脚本会自动优先使用项目 `.venv`，除非显式设置了 `LAB_PYTHON`。检查该覆盖值：

```powershell
$env:LAB_PYTHON
```

```powershell
Remove-Item Env:LAB_PYTHON -ErrorAction SilentlyContinue
```

```powershell
if (-not (Test-Path .env)) {
```

```powershell
pnpm package --win --x64
```


`_internal/` 包含 Python 运行库及控制端依赖，不能省略。最终用户无需安装 Python、pyserial 或设置 `LAB_PYTHON`；USB 转串口驱动、接线、端口及设备地址仍须与现场硬件匹配。

### Windows 通信检查阶段出现 `3221225477` 时

`3221225477`（十六进制 `0xC0000005`）是 Windows 访问冲突状态。如果日志已显示 PyInstaller `Build complete!`，随后在 `controller:check` 退出，说明构建已完成，失败发生在检查阶段；不能据此认定缺少 Python、PyInstaller 打包失败或硬件协议错误。

本次 Windows 现场已确认：Node.js 22.23.3 x64，在中文/空格临时路径下创建目录成功，随后 `fs.cpSync` 复制控制端目录时以 `0xC0000005` 崩溃，尚未启动控制端。这定位了崩溃调用，但不证明底层一定是 Node、文件系统或其他系统组件中的哪一个问题。

检查脚本现已通过 `scripts/copy-controller.mjs` 改为递归遍历、逐文件普通读取/写入，避免 `cpSync` / `copyFileSync` 的原生快速复制路径；保留完整资源、空目录、Unix 可执行权限及相对符号链接。同步修改后，已有成功构建的控制端可直接执行 `node scripts/check-controller.mjs` 复测，无需重新运行 PyInstaller。此规避方案仍待 Windows 实机确认；通过后再运行完整打包。

先在项目根目录的 PowerShell 中确认实际运行时，再单独运行检查，避免反复重建：

```powershell
(Get-Command node).Source
node -p "JSON.stringify({execPath:process.execPath,node:process.versions.node,bun:process.versions.bun,platform:process.platform,arch:process.arch})"
pnpm exec node -p "JSON.stringify({execPath:process.execPath,node:process.versions.node,bun:process.versions.bun,platform:process.platform,arch:process.arch})"
node scripts/check-controller.mjs
$LASTEXITCODE
```

使用官方 Node.js x64，推荐 24 LTS；`node` 命令不应由 Bun 替代。`pnpm exec node` 与直接调用 `node` 的输出可用于检查脚本环境是否改变了解释器路径。日志格式本身不能证明使用了哪种运行时。

新版检查脚本会同步输出运行时、创建临时目录、复制完成、启动、子进程 PID、握手、ping、退出和清理等阶段：

- 若检查脚本直接以访问冲突退出且没有 JavaScript 错误栈，保留最后一条阶段日志，用来缩小运行时或原生调用的故障范围。
- 若独立控制端退出，脚本会报告子进程十进制及十六进制退出码、signal 和 stderr，以区别于检查脚本自身崩溃。
- 仅缺少下一阶段日志不能单独证明根因。请保留完整输出、Node 版本/路径，以及必要时 Windows 事件查看器中的故障应用和故障模块记录，继续定位。

本机 macOS 的检查通过不能证明该 Windows 原生崩溃已经修复。不要跳过通信检查生成交付安装包，不要为排错直接运行运动指令，也不建议未确认原因就关闭系统安全软件。

### 生成安装包

`pnpm package` 依次执行：

1. TypeScript 检查和应用构建。
2. 清理专用控制端产物目录，以 PyInstaller **onedir / console** 模式构建完整控制端（保留 stdin/stdout JSONL）。
3. 将整个控制端复制到带中文和空格的临时路径，以全新临时数据目录验证 `ready`、`system.ping`、`system.shutdown` 和正常退出；不发送运动指令，结束后清理进程与临时目录。
4. 准备原有配置资源，再调用 electron-builder；打包前校验控制端平台、架构及文件，打包后检查安装资源内的可执行文件和运行库目录。任一步失败即终止，不允许跨平台/跨架构混装。

不要绕过以上流水线，直接用 `pnpm exec electron-builder` 生成交付安装包。各阶段可单独诊断：

```sh
pnpm controller:build
pnpm controller:check
```

产物位置：

| 路径 | 内容 |
| --- | --- |
| `out/` | Electron 应用编译产物 |
| `dist/controller/lab-controller/` | 完整独立控制端目录，不能仅分发其中的可执行文件 |
| `dist/controller-build/` | PyInstaller 工作、spec 和缓存文件 |
| `dist/installers/` | 安装包和 electron-builder 解包产物 |

安装资源内为 `resources/controller/lab-controller.exe`（Windows）或 `resources/controller/lab-controller`（本机其他平台），旁边是 `_internal/` 运行依赖。安装后不依赖系统 Python，不使用 `LAB_PYTHON` 或开发源码 `PYTHONPATH`；内置程序缺失、启动失败或握手超时会明确报错，不回退系统 Python。开发运行仍使用原有 Python 模块方式。

`hardware.json` 结构、用户数据目录及首次运行初始化不变；安装资源不包含开发电脑的硬件配置和数据。已有 `export.env`、调试授权配置准备流程与图标资源保持不变。构建产物及虚拟环境不提交 Git。

当前平台目标仍为 Windows NSIS、macOS DMG 和 Linux AppImage；优先交付 Windows x64。不新增签名、公证、自动更新。**本机验证不等于 Windows 安装或真实硬件验收通过**，最终验收及待办见 [内置控制端验证记录](docs/016.内置控制端构建与验证记录.md)。完成目标 Windows 无 Python 环境及现场硬件验收前，不标记正式交付就绪。
